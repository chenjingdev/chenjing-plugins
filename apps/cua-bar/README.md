# CUA Bar

앱 하나만 깔면 Claude Code에서 CUA(화면 조작)를 쓸 수 있어요. CUA Bar가 Claude Code에 CUA 연결(MCP)을 깔고 지우고, 환경이 잘 설정됐는지 점검하고, 새 판이 나오면 스스로 올려요. Claude 플러그인은 따로 깔지 않아요. 메뉴 막대에서 상태를 보여 주고, AI가 정리 없이 끝나며 남긴 브라우저 점유를 풀어 주는 맥 메뉴 막대 앱이기도 해요. 이름은 가칭이에요.

연결 자체는 앱에 담긴 엔진(`engine/`, 설명은 [engine/README.md](engine/README.md))이 해요. 앱은 켜질 때 엔진을 `~/.local/share/codex-cua/engine/<판>/`에 풀어 두고, 엔진의 `codex-cua` 명령을 불러 상태를 읽고, 돌려받은 것을 보여 줄 뿐이에요.

Apple Silicon Mac, macOS 14 이상에서 돌아요. Computer Use를 쓸 수 있는 Codex 앱이 있어야 하고, Claude가 붙으려면 Claude Code도 있어야 해요. 앱 판 번호는 앱에 담긴 엔진의 판 번호와 늘 같아요(`engine/.claude-plugin/plugin.json`의 `version`).

## 받아서 켜기

받는 곳은 https://cua.chenjing.org 예요. 셋 중 편한 것으로 깔아요.

- **브라우저로 받기**: https://cua.chenjing.org 를 맥 브라우저로 열면 dmg가 바로 받아져요. dmg를 열고 `CUABar.app`을 Applications(응용 프로그램) 폴더로 끌어 놓은 뒤 열어요. 홈 폴더 안의 `~/Applications`도 돼요.
- **터미널 한 줄**: `curl -fsSL https://cua.chenjing.org/install.sh | sh`. 최신 dmg를 받아 SHA-256을 확인하고, 서명을 요구 사항으로 검증한 뒤(서명에 적힌 글자를 읽는 것이 아니라 시스템이 인증서 사슬을 확인해요) `/Applications`(쓸 수 없으면 `~/Applications`)에 깔고 켜요. dmg는 열기 전에 팀 S3KC8R8VDL의 Developer ID로 서명한 것인지 보고, 그 안에서 꺼낸 앱은 그 팀의 CUA Bar가 맞는지 한 번 더 봐요. 하나라도 어긋나면 아무것도 깔지 않아요. 이미 같거나 새 판이 있으면 받지 않고 켜기만 해요. 켜져 있던 옛 판은 끄고 바꿔요.
- **에이전트에게 맡기기**: "CUA Bar를 설치해 줘. https://cua.chenjing.org/install"이라고 말하면 돼요. 그 주소는 에이전트가 읽는 설치 안내예요.

받는 곳에는 `SHA256SUMS.txt`도 있어요. 받은 폴더에서 `shasum -a 256 -c SHA256SUMS.txt`를 실행해서 `OK`가 나오면 파일이 온전한 거예요. 같은 파일을 [GitHub Releases](https://github.com/chenjingdev/chenjing-plugins/releases)(태그 `cua-bar--v<판>`)에도 올릴 때가 있지만, 앱의 자동 업데이트와 터미널 한 줄은 GitHub를 보지 않고 받는 곳만 봐요.

### 처음 열 때

앱과 dmg는 Developer ID로 서명했고 Apple 공증을 받았어요. 그래서 처음 열 때 macOS가 "인터넷에서 다운로드한 앱"이라며 한 번 물어요. **열기**를 누르면 되고, 다음부터는 묻지 않아요. 터미널 한 줄로 깔았으면 이 질문도 없어요.

## 켜면 하는 일

1. **묻지 않고 깔아요.** 앱을 깐 것이 곧 CUA를 쓰겠다는 뜻이라서, 앱은 켜질 때 아래를 알아서 깔아요. 빠졌거나 판이 다르면 다시 깔고, 바꿀 것이 없으면 말없이 끝나요.
   - **엔진**: 앱에 담긴 엔진을 `~/.local/share/codex-cua/engine/<판>/`에 풀고, `engine/current` 링크가 그 판을 가리키게 해요. 판마다 폴더가 따로라서 업데이트로 앱이 바뀌어도 열려 있는 Claude 대화와 켜져 있는 Codex의 연결이 끊기지 않아요. 옛 판 사본은 쓰는 프로세스가 없을 때만 지워요.
   - **파이썬 환경**: `~/.local/share/codex-cua/venv`에 필요한 패키지를 받아요. 첫 설치는 몇 분 걸릴 수 있고, 그동안 상태 카드가 "연결을 설정하는 중"이라고 말해요. 패키지가 바뀌는 판에서만 새로 만들어요.
   - **Codex 연결**: `~/.local/bin/codex-cua` 명령, Codex를 연결 가능한 방식으로 켜는 래퍼와 로그인 설정(`~/Library/LaunchAgents/com.chenjingdev.codex-cua.env.plist`), 중계기 사본이에요.
   - **Claude Code의 MCP**: `claude mcp add -s user cuabar -- ~/.local/share/codex-cua/engine/current/start-mcp.sh`로 한 번 등록해요. 판이 바뀌어도 `current` 링크가 새 판을 가리키니 다시 등록하지 않아요. CUA를 쓰는 법은 이 MCP가 Claude 대화에 붙을 때(`instructions`) 알려 주고, 그때만 필요한 안내는 그 오류 끝에 붙여요. 0.8.9까지는 `~/.claude/skills/cuabar/`에 스킬도 깔았는데, 앱이 디스크에 바로 쓰는 스킬과 이미 떠 있는 MCP가 서로 다른 판의 말을 할 수 있어서 0.8.10부터 깔지 않아요(남아 있으면 점검 탭이 알려요).

   바뀐 것이 있으면 "새 Claude 대화부터 CUA가 붙어요"라고 한 번 알려요. 이미 열려 있는 Claude 대화에는 붙지 않아요. 실패하면 카드에 "연결 설정에 실패했어요"와 **다시 하기** 버튼이 떠요. 저절로 하는 것은 앱을 켤 때마다 한 번과, 켤 때 없어서 미룬 것이 나중에 생겼을 때 한 번이에요. 그 밖에는 버튼을 누를 때만 해요.
2. **없는 것은 미뤄요.**
   - Claude Code가 없으면 엔진까지만 깔고 MCP는 미뤄요. 이 줄은 점검 탭에만 나오고 상태 카드와 아이콘은 문제로 보이지 않아요(Codex만 쓰는 맥이 늘 문제로 보이지 않게). Claude Code가 생기면 알아채고 한 번 깔아요.
   - Codex 앱이 없으면 엔진도 MCP도 깔지 않아요. 상태 카드와 아이콘이 "Codex 앱이 없어요"와 **받는 곳 열기**를 보여요. Codex가 깔리면 알아채고 한 번 깔아요.
   - 개발자 도구가 없으면 설치 창을 저절로 띄우지 않고(앱이 앞으로 나서지 않게), 카드에 "개발자 도구 필요"와 **설치** 버튼만 둬요. 누르면 macOS의 개발자 도구 설치 창이 떠요. 끝난 뒤 한 번 더 누르면 이어서 깔아요.
3. **남의 것은 건드리지 않아요.** 앱이 깔지 않은 `cuabar` MCP, 옛 `cua@chenjing-plugins`·`cua@ubion` 플러그인, 0.8.0이 `cua`라는 이름으로 깐 MCP와 스킬, 0.8.9까지 깐 `cuabar` 스킬이 있으면 지우거나 덮지 않고, 점검 탭에 충돌이나 남은 것과 지우는 명령을 보여요. 앱 표식(`.cua-bar.json`)이 없는 `~/.claude/skills/cuabar`는 사용자가 만든 스킬이라서 말하지 않아요. Claude Code 설정 파일도 고치지 않아요. 아래 "옛 플러그인에서 옮기기"를 보세요.
4. **로그인할 때 저절로 떠요.** Applications나 `~/Applications`에서 처음 열 때 한 번만 로그인 항목으로 등록해요. 그 뒤로는 다시 등록하지 않아요. 끄고 싶으면 시스템 설정 → 일반 → 로그인 항목에서 끄면 되고, 앱이 그것을 존중해요. 앱 안에는 스위치가 없어요. 지금 상태는 점검 탭의 앱 로그인 항목 줄과, 기록 탭 아래쪽(진단 복사 버튼 줄 위)에 적혀요.
5. **Codex를 한 번 다시 켜야 해요.** 이미 켜져 있던 Codex는 연결 없이 켜진 것이라, 카드가 "Codex가 연결 없이 켜져 있어요"라고 하고 **다시 켜기**를 보여요. 앱은 누르기 전에는 Codex를 끄지 않아요. 버튼 옆에 "하던 Codex 작업이 끊겨요"라고 적혀 있고, 누르면 다시 묻지 않고 정상 종료(강제 종료 없음)한 뒤 다시 켜요. macOS가 CUA Bar가 Codex를 제어하려 한다고 물으면 **허용**을 눌러요. 종료 요청이 그 권한으로 가요. Codex가 종료를 한 번 더 물으면(예약 작업이 있으면 Codex가 물어요) Codex 창에서 **종료**를 눌러 주세요. 그동안 카드가 꺼지기를 기다린다고 말하고, 10분 안에 꺼지면 앱이 Codex를 다시 켜요. 그 뒤로는 Dock이나 Spotlight로 켜도 Claude가 바로 붙고, Codex가 꺼져 있으면 Claude 대화를 열 때 뒤에서 켜져요.

## 화면

**아이콘**은 하나이고, 모양으로 구분해요: 준비(체크가 든 원), 작업 중(도는 화살표), 문제(경고 삼각형, 주황색). 올려 두면 한 줄 요약이 떠요. 누르면 팝오버가 열려요.

**상태 카드**는 맨 위에 있어요. 지금 상태, 한 줄 제목, "다음에 할 일"이 있고, 앱 전체에 문제가 있을 때만 고치는 버튼이 하나 있어요. 연결 하나의 문제(끝난 연결, 남은 점유)는 카드가 말만 하고, 누르는 버튼은 아래 목록 맨 위 그 줄에 있어요. 누를 곳은 늘 한 군데예요. 문제가 없어도 Codex를 다시 켜면 나아지는 것이 있을 때는(중계기 없이 켜졌거나 업데이트 전의 래퍼로 켜진 Codex) 카드가 그렇게 말하고 **다시 켜기**를 보여요(0.8.4부터). 앱은 스스로 다시 켜지 않으니 Codex가 쉴 때 눌러요. 문제 카드의 다시 켜기처럼 끊기는 작업을 버튼 옆에 적어 두고, 누르면 다시 묻지 않아요. Claude 대화가 Codex를 거쳐 CUA를 쓰는 중이거나 무언가를 잡고 있으면 그 글이 "하던 Codex 작업과 Claude 대화의 CUA 작업이 끊겨요"예요. 그 Claude 대화는 다음 호출 때 새 Codex에 다시 붙어요.

| 문제 | 버튼 | 누르면 |
|---|---|---|
| Codex 앱이 없어요 | 받는 곳 열기 | Codex를 받는 페이지를 브라우저로 열어요 |
| 개발자 도구 필요 | 설치 | macOS의 개발자 도구 설치 창을 열어요. 끝난 뒤 한 번 더 누르면 위 "켜면 하는 일" 1번의 설치를 이어서 해요 |
| 연결 설정에 문제가 있어요 (엔진·파이썬 환경·Codex 래퍼와 로그인 설정·중계기·Claude Code의 MCP가 빠졌거나 깨졌거나 앱과 판이 달라요) | 고치기 (한 번 실패한 뒤에는 다시 하기) | 위 "켜면 하는 일" 1번의 설치를 다시 해요. 같은 판 엔진이 온전하면 그대로 두고 깨진 설정만 다시 맞춰요 |
| Codex가 연결 없이 켜져 있어요 | 다시 켜기 | 끊기는 작업을 버튼 옆에 적어 두고, 누르면 묻지 않고 정상 종료한 뒤 다시 켜요 |
| CUA 상태를 읽지 못했어요 | 다시 읽기 | 상태를 다시 읽어요 |

"끝난 연결이 남아 있어요"와 "점유가 남았을 수 있어요"에는 카드 버튼이 없어요. 카드가 그 줄의 버튼 이름으로 "목록 맨 위의 정리를 눌러 주세요"(남은 점유면 "목록 맨 위의 탭 풀기를 눌러 주세요")라고 말하고, 연결 탭 맨 위의 **손볼 것**에서 눌러요. 지금 Codex가 남은 점유의 풀기를 막고 있으면(아래 **손볼 것**, 0.8.8부터) 그 점유는 문제로 세지 않아요. 그것뿐이면 카드는 평소 상태이고, 될 수 없는 일을 시키지 않아요.

앱이 건드리지 않는 것이 문제일 때도 카드에는 버튼이 없어요. Claude Code에 앱이 깔지 않은 cuabar MCP가 있다는 카드와 "Codex 로그인 설정이 다른 값과 겹쳐요" 카드는 "점검 탭에서 치우는 방법을 보세요"(겹치는 값이면 "겹치는 값과 치우는 방법을 보세요")라고만 말하고, 방법은 점검 탭에 있어요. 문제가 여럿이면 가장 먼저 걸리는 하나만 카드에 보여요. 버튼이 있는 문제가 먼저예요.

그 아래에 탭이 셋 있어요: 연결, 기록, 점검.

- **연결**: Claude, Codex, cmux-cua의 연결과 남은 브라우저 점유가 한 목록에 있어요. 맨 위에는 지금 화면을 쓰는 연결이 한 줄 보여요.
  - **손볼 것**: 끝난 연결, 주인이 사라진 점유, 주인 없는 cmux-cua 연결이 맨 위에 모여요. 줄마다 버튼이 하나예요. 끝난 연결과 주인 없는 cmux-cua 연결은 **정리**(탭을 풀고 남은 연결을 꺼요. 제때 안 꺼지면 강제로 꺼요), 남은 점유는 **탭 풀기**(그 세션이 남긴 점유만 풀어요)예요. 앱이 끌 수 없는 끝난 연결은 탭만 풀고 그 까닭을 줄에 적어요. AI가 이미 없어서 묻지 않아요. 연결이 아직 잡고 있는 세션은 그 줄의 버튼(끝난 연결은 정리, 살아 있는 연결은 탭 풀기)이 푸는 길이라서, 점유 줄을 따로 두지 않고 카드에도 세지 않아요(한 세션이 두 줄로 보이지 않게). 그 줄의 버튼을 누를 수 없을 때는 점유 줄이 남고 확장 초기화 안내가 열려요. Codex 26.1023부터 Codex는 앱이 시작하거나 다시 연 대화만 브라우저를 쓰게 해서, 엔진이 연 대화(Claude 연결의 대화와 탭 풀기용 숨은 대화)는 늘 거절돼요. 그래서 Claude 대화가 남긴 점유를 세션 ID로 푸는 탭 풀기(모두 정리와 자동 정리 포함)는 `browser_blocked`로 끝나고(0.8.7부터), 그 줄에는 "Codex가 Claude 대화의 브라우저 사용을 막아서 풀 수 없어요" 한 줄만 적혀요. 사용자가 끈 설정도 확장 문제도 아니라서 확장 초기화 안내는 열리지 않고 보던 탭도 그대로예요. 모두 정리는 처음 막히면 남은 세션을 더 묻지 않고, 자동 정리는 그 뒤 앱을 다시 켤 때까지 남은 점유(세션)를 시도하지 않고, 끝난 연결의 정리는 그대로 해요(연결은 브라우저를 거치지 않아요). 살아 있는 연결이 잡은 점유는 주인이 있으니 "점유가 오래 남았어요" 알림도 없어요. 정리가 연결의 탭을 풀고 그 놓아주기가 첫 물음에 확인되면 엔진이 그 세션을 죽은 다리 기록에서도 바로 지워요. 두 번째 물음에서야 확인되면 자동 정리가 이어서 세션 ID로 브라우저를 불러 풀고 지워서, 어느 쪽이든 점유가 남았을 수 있다는 줄이 되살아나지 않아요. 앱이 정리할 줄이 둘 이상이면 머리에 **모두 정리**가 생겨 한 번에 정리해요. 한 줄뿐이면 그 줄의 버튼만 있어요. Codex 대화가 남긴 점유는 그 줄의 탭 풀기로만 풀어요. Codex 대화는 다시 열 수 있어서, 넘겨주려고 남긴 탭까지 닫지 않으려고요.
  - **Claude · n**, **Codex · n**: 살아 있고, 지금 일하는 중이거나 무언가를 잡고 있는 연결이에요. 잡고 있다는 건 AI가 CUA를 부른 뒤 아직 턴을 끝내지 않았거나(`turn_ended`), Codex가 다시 켜지기 전에 잡은 점유가 Chrome에 남았을 수 있다는 뜻이에요. AI가 턴을 끝냈거나 탭 풀기로 놓아서, 또는 아직 CUA를 부르지 않아서 잡은 것이 없는 연결은 목록에도 카드의 연결 수에도 넣지 않아요(0.8.2부터). 그런 연결도 맨 아래 "확장을 껐다 켜면 끊길 살아 있는 연결"에는 보여요. 턴을 끝내는 `turn_ended`는 화면을 쓴 호출로 치지 않아요. 그래서 탭 풀기를 해도 그 줄이 '사용 중'이 되지 않아요. 줄마다 작업 폴더, 시작 시각, 메모리, 상태(사용 중 · 쉼 n분 · 알 수 없음)가 보여요. 버튼은 **탭 풀기** 하나예요. 그 AI가 잡은 브라우저 탭만 풀고, AI는 화면 도구를 계속 써요. 누르면 묻지 않고 풀어요. 일하는 중인 연결은 버튼에 마우스를 올리면 하던 브라우저 작업이 끊길 수 있다고 보여요. 하던 호출이 아직 끝나지 않아 엔진이 풀기를 거절하면 그 줄에 "작업이 끝나지 않아 못 풀었어요"가 적히고, 호출이 끝난 뒤 탭 풀기를 다시 누르면 돼요. 앱은 살아 있는 AI의 연결을 끄지 않아요. 그만 쓰려면 그 AI 쪽에서 끄면 돼요.
  - **cmux-cua**: 켜져 있는지와, AI 대화마다 붙은 연결(`cmux-cua mcp`)이 한 줄씩 보여요. 살아 있는 연결은 보기만 하고, 띄운 AI가 사라진 연결만 손볼 것에서 정리해요. cmux-cua 본체와 AI 앱은 끄지 않아요.
  - **Codex가 막아서 풀 수 없는 점유**(0.8.8부터): 탭 풀기가 `browser_blocked`로 끝나면 엔진이 그때의 Codex 앱 판을 적어 두고, 같은 판이 깔려 있는 동안 `status --json`이 `leases.release_blocked`를 참으로 내요. 그동안 주인이 사라진 점유 줄은 "Codex가 막아서 풀 수 없음 · 18:48에 끝남"처럼 보이고, 버튼은 **지우기**예요. 지우기는 점유를 풀지 않고 목록에서만 빼요(`codex-cua dismiss-session`). Chrome 탭과 Codex는 그대로예요. 목록 위에는 "Codex가 브라우저를 막아서 남은 점유를 풀 수 없어요. 지워도 돼요. Chrome 탭이 막히면 그 탭을 닫거나 Codex 확장을 껐다 켜요." 한 줄만 나오고, "점유 목록을 읽지 못해서…" 줄은 이 줄로 합쳐요. **모두 정리**는 이 줄들을 풀지 않고 지우고, 다른 줄은 전처럼 정리해요. 이 줄들에는 "1분 넘게 안 풀림" 알림이 없고, 자동 정리도 풀어 보지 않아요(끝난 연결은 전처럼 정리해요). 살아 있는 연결이 쥔 점유는 지울 수 없어서 버튼 대신 까닭을 적어요. Codex 판이 바뀌면 전처럼 탭 풀기가 다시 보여요. 무엇을 지울지는 사용자가 골라요.
  - 맨 아래 **브라우저 탭이 계속 막히면**: "막힌 탭 닫기"를 먼저, 그래도 안 되면 "확장 껐다 켜기"를 안내하고, 확장을 껐다 켜면 끊길 연결의 목록을 보여요. 하나씩 풀 방법이 없는 점유가 있거나, 탭 풀기가 확장 쪽 까닭(`unsupported`·`cleanup_not_confirmed`·`timeout`)으로 실패하면 펼쳐져요. Codex가 브라우저를 막아 `browser_blocked`로 끝난 탭 풀기에는 펼쳐지지 않아요. 확장을 껐다 켜도 풀리지 않아서요. 그 대화로는 브라우저 일을 할 수 없으니 Codex 앱에 직접 시켜요. 데스크톱 앱 조작은 그대로 돼요.
- **기록**: 최근 조작(시각 · 에이전트 · 폴더 · 도구 · 성공 여부 · 걸린 시간)이에요. 오늘이 아닌 줄은 시각 앞에 날짜가 붙어요. 실패한 줄에는 까닭이 따로 있을 때 도구 옆에 빨간 글씨로 보여요(0.8.4부터 쓴 줄): **시간 초과**는 화면 조작이 정한 시간(없으면 30초)을 다 쓴 것이고, **화면 잠김**은 Mac이 잠겨 있어서 막힌 것이고, **잠금 해제 실패**는 Mac이 잠겨 있는데 Codex CUA 서비스의 자동 잠금 해제가 풀지 못한 것이에요(0.8.5로 올린 뒤 새로 연 대화의 줄부터. 그 전에는 화면 잠김으로 적혔어요). 앱이 그 서비스를 다시 켠 줄은 에이전트 자리에 **CUA Bar**, 도구 자리에 **CUA 서비스 다시 켜기**로 보여요(아래 "잠긴 Mac에서 자동 잠금 해제가 막히면"). 탭 머리의 **오류 문구 남기기**를 켜면 그 뒤로 실패한 호출이 답한 오류 문구도 실패 줄 아래에 세 줄까지 보여요(500자까지 남기고, 마우스를 올리면 전부 보여요). 문구에 화면이나 페이지의 글자가 섞일 수 있어서 처음엔 꺼져 있고, 진단 복사에는 넣지 않아요. 끄면 새로 남기지 않고 이미 남은 문구도 보이지 않아요. 켜기 전에 실패한 줄과 이미 열려 있던 옛 판 Claude 대화의 줄에는 문구가 없어요. 폴더는 그 줄을 쓴 쪽이 함께 적은 작업 폴더라서 대화가 끝나 연결이 사라진 뒤에도 보여요(0.8.2부터 쓴 줄. 그 전 줄은 연결이 목록에 있을 때만 보이고 아니면 "—"예요). 맨 아래에 가끔 쓰는 버튼이 모여 있어요. **진단 복사**는 붙여 넣어도 안전한 진단 글을 복사하고, 끝에 점검 결과(항목마다 한 줄), 알림 상태, 앱 판, 로그인 항목, 업데이트 줄을 차례로 덧붙여요(경로·판·상태 낱말만 들어가요). 업데이트 줄은 새 판을 저절로 올리지 못했으면 그 기록이고, 정식 서명 판이 아니라서 업데이트를 하지 않는 빌드이면 "업데이트: 꺼짐(정식 서명 판이 아님)"이에요. 할 말이 없으면 이 줄은 없어요. Codex가 이미 끝난 대화의 스레드를 스스로 다시 켠 빈 런타임은 목록에 보이지 않고, 있으면 이 글에 "Codex가 다시 켠 빈 런타임 n개 · 메모리" 한 줄로만 들어가요(Codex가 곧 내려요). 알림을 보일 수 없을 때만 **알림 켜기**가 보여요. **앱 지우기**는 아래 "지우기"를 보세요.
- **점검**: 환경을 항목마다 한 줄씩 보여요. 줄마다 상태와 짧은 설명이 있고, 순서는 이래요.
  1. **Claude Code**: 찾았는지. 없으면 받는 법을 한 줄로 알려요. 찾았지만 시작하지 못하면(npm으로 깐 `claude`가 옆의 `node`를 못 찾을 때처럼) 찾은 `claude`의 경로와 "터미널에서 그 claude가 도는지 확인해 주세요"를 보여요.
  2. **MCP**: Claude Code에 `cuabar` MCP가 앱이 깐 것으로 들어 있는지. Claude Code 쪽 준비는 이 줄 하나로 판정해요(0.8.10부터 스킬 줄은 없어요). 옛 플러그인(`cua@chenjing-plugins`, `cua@ubion`)이나 0.8.0이 깐 옛 이름 `cua` MCP가 남아 있으면 CUA가 둘 붙는다고 이 줄에 적어요. 0.8.0이 깐 옛 이름 `~/.claude/skills/cua`와 0.8.9까지 깐 `~/.claude/skills/cuabar`가 앱 표식과 함께 남아 있어도 이 줄에 지우는 명령과 함께 적어요("0.8.9까지 깐 cuabar 스킬이 남아 있어요 — 이제 MCP가 안내해요", `rm -rf ~/.claude/skills/cuabar`).
  3. **허락 규칙**: Claude Code가 CUA를 부를 때 묻는지(0.8.6부터). 사용자 설정(`~/.claude/settings.json`)에 cuabar를 가리키는 규칙이 없고 기본 모드가 `bypassPermissions`가 아니면 **안내**로 규칙 `mcp__cuabar` 한 줄을 보여 줘요. Claude Code에서 `/permissions`를 열고 허용(Allow)에 그 규칙을 더해 User settings에 저장하면 어느 폴더에서든 묻지 않고, auto 모드에서도 CUA 호출은 auto 모드 검사를 건너뛰어요. 옛 도구 이름(`mcp__cua__…`, `mcp__plugin_cua_cua__…`)을 적은 허락 규칙이나 훅이 사용자 설정이나 프로젝트 폴더의 `.claude/settings.json`·`.claude/settings.local.json`에 있으면 **문제**로 그 파일을 두 곳까지 보여요. 규칙은 CUA를 이미 묻지 않게 해 두었으면 아무것도 바꾸지 않아서 말하지 않고, 훅은 다시는 돌지 않아서 늘 말해요. 프로젝트 폴더는 `~/.claude.json`에 적힌 홈 폴더 안의 폴더와 그 git 맨 위 폴더(Claude Code의 "다시 묻지 않기"가 저장되는 곳)이고, 1분에 한 번만 다시 읽어요. macOS가 허락을 묻는 `Desktop`·`Documents`·`Downloads`·`Library` 안과 링크를 거치는 폴더는 읽지 않아요(허락 창이 뜨지 않게).
  4. **엔진**: 엔진 사본의 판이 앱의 판과 같은지.
  5. **파이썬 환경**: 필요한 패키지가 준비됐는지.
  6. **Codex 래퍼와 로그인 설정**: Codex를 연결 가능한 방식으로 켜는 래퍼와 로그인 설정이 제자리에 있는지.
  7. **중계기**: 중계기 사본이 온전한지, 지금 켜진 Codex에 붙어 있는지. 사본은 온전한데 Codex가 중계기 없이 켜져 있으면 대기로 그 까닭을 적어요. 0.8.2까지는 Codex가 스스로 업데이트된 뒤 처음 켜질 때마다 그랬어요. Codex가 새 판의 플러그인 사본을 래퍼가 살펴본 뒤에야 쓰기 때문이에요. 0.8.4부터는 사본이 아직 없으면 Codex 앱 안의 플러그인 원본을 대신 읽어서, 업데이트 뒤에도 다시 켜지 않고 붙어요. Codex 26.1023은 번들 정의에 `--import …/require-browser-access.mjs`를 더했는데, 0.8.6까지는 이것을 번들이 아닌 정의(`not_bundled`)로 보고 중계기를 빼서 Codex 대화의 연결이 목록에 안 보였어요. 0.8.7부터는 같은 플러그인의 그 모듈 하나를 앞에 둔 모양을 번들 정의로 받아들여요. 이전 판 래퍼로 켜진 Codex는 카드가 "Codex를 다시 켜면 중계기가 붙어요"라고 말하고 **다시 켜기**를 보여요. 0.8.9부터는 업데이트 직후 첫 시작에서 래퍼가 이전 판 폴더의 모듈을 읽어 중계기를 뺀 경우도(`plugin_updating`) 새 사본이 써지고 나면 같은 안내를 해요. 다시 켜면 새 정의를 읽어 붙어요. 원본이 맞지 않아 빠졌는데 Codex가 켜진 뒤에 사본이 생겼으면 카드가 "Codex를 다시 켜면 중계기가 붙어요"라고 말하고 **다시 켜기**를 보여요. 다시 켜도 붙지 않을 까닭이면 그 말은 없어요. 그 전까지 Codex 대화의 연결은 목록에 보이지 않고 탭도 풀 수 없어요.
  8. **앱 로그인 항목**: CUA Bar가 로그인할 때 뜨도록 등록돼 있는지.
  9. **Codex 호스트와 연결 시험**: 연결 가능한 방식으로 켜진 Codex가 있는지, 그리고 실제로 붙는지.

  깨진 줄이 상태 카드에도 올라 있으면(MCP·엔진·파이썬 환경·래퍼·중계기, 그리고 Codex 앱이 없거나 Codex가 연결 없이 켜져 있을 때의 Codex 호스트 줄) 줄에는 "위 카드에서 고쳐요"만 적고, 카드의 버튼으로 고쳐요. 카드에 오르지 않는 줄은 그 줄에서 고쳐요.
  - 개발자 도구: **설치** 버튼이에요. 누를 때만 macOS 설치 창이 떠요.
  - 앱이 깔지 않은 `cuabar` MCP나 옛 플러그인: 지우는 명령(`claude mcp remove -s user cuabar`, `claude plugin uninstall cua@chenjing-plugins --scope user`, `claude plugin uninstall cua@ubion --scope user`)을 보여 줘요. 0.8.0의 옛 이름은 `claude mcp remove -s user cua`와 `rm -rf ~/.claude/skills/cua`, 0.8.9까지 깐 스킬은 `rm -rf ~/.claude/skills/cuabar`예요(앱이 깐 것일 때만 보여요). 명령은 복사 버튼으로 줘요. 앱이 대신 하지 않아요.
  - Codex 로그인 설정이 남의 값과 겹칠 때: 겹치는 것과 치우는 법을 보여요. 로그인 항목 파일이 남의 것이면 그 파일을 다른 곳으로 옮기라고, `CODEX_CLI_PATH`가 남의 값이면 그 값(읽기만 해요)과 `launchctl unsetenv CODEX_CLI_PATH`(복사 버튼)를 보여 주고 지운 뒤 카드의 고치기를 누르라고 안내해요.
  - 허락 규칙: 규칙 `mcp__cuabar`를 복사 버튼으로 줘요. 옛 이름의 규칙과 훅은 파일을 보여 주고 지우거나 `mcp__cuabar`(훅의 matcher는 `mcp__cuabar__`)로 바꾸라고 해요. 앱은 설정 파일을 고치지 않아요.
  - Claude Code 없음: 이 탭에만 나와요. 상태 카드와 아이콘은 문제로 보이지 않아요. 옛 플러그인과 옛 이름, 허락 규칙도 이 탭에만 나와요.

  Codex가 꺼져 있으면 연결 시험을 건너뛰고 "Claude 대화를 열면 켜져요"라고만 해요. 점검이 Codex를 켜지는 않아요. 켜져 있으면 마지막 결과와 시각, **연결 시험** 버튼이 있어요. 시험은 숨은 스레드에서 `cua.getState()`만 한 번 부르고 바로 정리해서, 연결 목록·기록·작업 중 표시·끝난 연결에 남지 않아요. 켜질 때는 시험하지 않고, 이 버튼을 누를 때와 설치나 업데이트가 무언가를 바꾼 직후 한 번만 해요.

  점검은 `~/.claude.json`, 옛 스킬 폴더, Claude Code 설정 파일을 읽기만 해요. 서버를 띄워 시험하는 `claude mcp list`는 쓰지 않아요.

목록이 비어 있으면 "연결 없음", "기록 없음"처럼 한 줄로 말해요.

어떤 버튼도 누른 뒤에 다시 묻지 않아요(0.8.4부터). 끊기는 것이 있으면 누르기 전에 보여요. 카드의 **다시 켜기**는 버튼 옆에 적혀 있고, 일하는 연결의 **탭 풀기**와 **앱 지우기**는 마우스를 올리면 보여요. 결과는 누른 버튼 옆에 나와요. 줄의 버튼은 그 줄에 한 줄로 나와요. **모두 정리**의 결과는 손볼 것 머리 밑에, **진단 복사**의 결과는 그 버튼 바로 위에 나와요. 그사이 줄이 사라졌거나 다른 탭으로 옮겼으면 맨 위에 나와요.

**맨 아래 줄**에는 상태를 읽은 시각, 새 판을 저절로 올리지 못했을 때만 **새 버전 x.y.z**(받는 곳을 열어요), 그리고 **끝내기**가 있어요.

AI가 정리 없이 끝나면 앱이 끝난 연결의 점유를 대신 풀어 줘요. 잠긴 Mac에서 CUA 서비스의 자동 잠금 해제가 막히면 그 서비스를 다시 켜 줘요(아래). 알림은 네 가지뿐이에요: 연결 없이 켜진 Codex를 다시 켤지 묻는 알림(**다시 켜기** 버튼이 있어요), 주인이 사라진 점유가 1분 넘게 안 풀렸다는 알림(점유마다 한 번), CUA 서비스를 다섯 번 다시 켜도 Mac 잠금이 풀리지 않았다는 알림(잠금마다 한 번, 누르면 기록 탭이 열려요), 업데이트 알림(새 판으로 올린 뒤 하나, 저절로 올리지 못했을 때 판마다 한 번. 올린 뒤의 알림에 점검 탭을 보라는 한 줄이 붙었으면 누를 때 점검 탭이 열려요). 알림을 꺼 두었으면 문제는 아이콘과 상태 카드에만 보여요(업데이트가 끝났다는 말은 창 안의 배너로만 나와서 창이 닫혀 있으면 못 보고, 앱 판은 진단 복사의 앱 판 줄에 있어요). **알림 켜기**는 알림을 아직 허용하지 않았으면 macOS의 질문을 다시 띄우고(화면이 잠긴 동안 앱이 켜지면 macOS가 묻지 못해요), 꺼 두었으면 시스템 설정의 알림을 열어요. 알림 본문을 누르면 macOS가 CUA Bar를 앞으로 불러 창이 열려요. 그 창을 Escape 따위로 닫았는데 CUA Bar가 아직 앞이면 앱이 앞 자리를 직전에 쓰던 앱에게 돌려주고(그 앱이 이미 꺼졌으면 앞 자리를 내려놓아요), 바깥의 다른 앱을 눌러서 닫았으면 그 앱이 그대로 앞이에요. 메뉴 막대 아이콘으로 연 창은 앞 앱을 바꾸지 않으니 돌려줄 것도 없어요.

## 잠긴 Mac에서 자동 잠금 해제가 막히면

Codex의 CUA 서비스는 Mac이 잠겨 있으면 화면이 필요한 호출마다 스스로 잠금을 풀어 보는데, 한 번 잠길 때마다 두 번까지만 해 봐요. 두 번 다 실패하면 사람이 잠금을 풀 때까지 모든 호출을 곧바로 거절해요("automatic unlock could not unlock it"). 서비스가 새로 켜지면 다시 두 번을 해 봐요.

그래서 앱은 기록에 **잠금 해제 실패** 줄이 새로 생기면 엔진의 `codex-cua unlock-reset`을 불러 CUA 서비스를 끄고(정상 종료 신호만 보내요. 강제 종료는 하지 않아요), 다음 CUA 호출이 서비스를 다시 켜서 잠금 해제를 다시 해 봐요. 묻지 않고 하고, 화면에도 아무것도 띄우지 않아요. 엔진은 아래가 모두 맞을 때만 꺼요.

- 지금 이 사용자의 화면이 잠겨 있어요.
- 이번 잠금에서 다시 켠 것이 다섯 번보다 적어요.
- 이번 잠금이 시작된 뒤, 그리고 마지막으로 다시 켠 뒤에 잠금 해제 실패가 있었어요. 실패 한 번에 한 번만 다시 켜요.
- 도는 CUA 호출이 없어요(15초까지 기다려요).
- 꺼질 서비스가 이 사용자의 Codex Computer Use 앱 안에 있고, 실행 중인 프로세스가 OpenAI의 서명(`com.openai.sky.CUAService`, 팀 2DC432GLL2)을 갖고 있어요.

끄기 바로 전에 잠금을 한 번 더 보고, 그사이 누가 잠금을 풀었으면 끄지 않아요. 10초 안에 꺼지지 않으면 그대로 둬요. 다시 켠 일은 기록에 한 줄로 남고, 엔진은 그 줄로 이번 잠금에서 몇 번 켰는지 세요. 실제 입력이 있어서 자동 잠금 해제를 멈췄다는 거절과 ChatGPT 스레드에 이어 붙일 수 없다는 거절은 다시 켜도 나아지지 않아서 **화면 잠김**으로 적고 건드리지 않아요.

Claude 쪽은 cuabar MCP가 그 오류 끝에 붙이는 안내가 맡아요(0.8.9까지는 cuabar 스킬). 잠금 해제 실패로 막히면 30초쯤 기다렸다가 보기만 하는 호출로 다시 부르고, 다섯 번까지 해 봐요. 그래도 안 되면 사용자에게 잠금을 풀어 달라고 해요. 다섯 번 다시 켜도 풀리지 않으면 앱도 "Mac 잠금을 자동으로 풀지 못했어요" 알림을 잠금마다 한 번 보내요. 앱이 꺼져 있으면 아무도 다시 켜지 않아요.

## 새 판은 스스로 올라가요

앱은 https://cua.chenjing.org/version 한 곳만 봐요. 켜질 때 한 번, 그 뒤로 하루에 한 번 읽고, 지금 앱보다 높은 판이 있으면 묻지 않고 받아서 바꿔 끼워요.

1. **받아서 확인해요.** 파일은 받는 곳(cua.chenjing.org)에서만 받아요. `/version`이 알려 준 크기와 SHA-256이 맞아야 하고, 파일 이름은 `CUABar-v<판>-macos-arm64.dmg`여야 해요. 서명은 서명에 적힌 글자를 읽는 것이 아니라 요구 사항으로 검증해요: Apple이 뿌리인 Developer ID 인증서, 팀 S3KC8R8VDL, 앱은 `dev.chenjing.cua-bar`까지예요.
2. **팝오버가 닫혀 있을 때 바꿔 끼워요.** 팝오버가 닫혀 있고, 누른 버튼의 일·정리·설정·지우기·연결 시험이 돌지 않고, Codex 다시 켜기가 Codex 종료를 기다리는 중이 아닐 때 앱 자리를 새 앱으로 맞바꿔요(보는 중에 창이 사라지지 않게, 하던 일이 끊기지 않게요). 옛 앱은 `~/Library/Application Support/CUABar/Backups/<시각>/`에 하나만 남겨요. 조건이 안 맞으면 맞을 때까지 미뤄요.
3. **`open -g`로 다시 켜요.** 창을 앞으로 띄우지 않고 켜서, 하던 일을 방해하지 않아요. 켜진 새 판은 엔진과 MCP를 새 판으로 맞추고, Codex 호스트가 준비 상태이면 연결 시험을 한 번 한 뒤(Codex가 꺼져 있으면 시험하지 않아요) 시스템 알림 하나로 "CUA Bar를 x.y.z로 올렸어요. 새 Claude 대화부터 새 판이 쓰여요"라고 알려요. Claude Code에 CUA의 옛 이름(옛 플러그인, 0.8.0의 `cua` MCP·스킬, 옛 도구 이름을 적은 허락 규칙·훅)이 남아 있으면 "Claude Code에 CUA의 옛 이름이 남아 있어요 — 점검 탭을 보세요"가, 그렇지 않고 0.8.9까지 깐 `cuabar` 스킬이 남아 있으면 "0.8.9까지 깐 cuabar 스킬이 남아 있어요 — 점검 탭을 보세요"가(0.8.10부터), 그렇지도 않고 사용자 설정의 기본 모드가 `auto`인데 cuabar 규칙이 없으면 "auto 모드에서도 묻지 않게 하는 규칙 한 줄이 점검 탭에 있어요"가 본문에 붙고(0.8.6부터), 그 알림을 누르면 점검 탭이 열려요. 시험이 돌았는데 통과하지 못했으면 알림 본문 끝에 "연결 시험이 실패했어요 — 점검 탭을 보세요"가 붙어요. 알림을 꺼 두었으면 그 문장들은 창 안 배너의 업데이트 줄 끝에 붙어요. 어느 쪽이든 한 번만 말해요. Claude Code가 없는 맥은 업데이트 알림 없이 "연결 설정을 마쳤어요" 배너만 나와요(시험이 실패했으면 그 끝에 같은 문장이 붙어요).

열려 있던 Claude 대화와 켜져 있던 Codex의 연결은 끊기지 않아요. 엔진 사본이 판마다 따로 있기 때문이에요. 업데이트 전의 래퍼로 켜진 Codex는 앱이 끄지 않고, 카드가 "Codex를 다시 켜면 새 설정이 적용돼요"라고 말하며 **다시 켜기**를 보여요.

스스로 바꾸는 것은 Developer ID로 서명한 정식 판뿐이에요. 같거나 낮은 판, 번들 밖에서 돈 개발 빌드, 로컬에서 ad hoc 서명으로 만든 빌드는 확인도 버튼도 없이 그대로 둬요. ad hoc 서명으로 깐 맥은 정식 판을 한 번 손으로 깔기 전까지 저절로 올라가지 않아요.

받기나 확인에 실패하거나 앱 자리에 쓸 수 없으면(앱이 읽기 전용 폴더에 있을 때처럼) 지금 판을 그대로 두고, 창 아래 **새 버전 x.y.z** 버튼을 남겨요. 누르면 받는 곳이 열려서 직접 받을 수 있어요. 판마다 한 번 "저절로 올리지 못했어요" 알림도 보내요. 실패한 판은 다음 하루 확인이나 다음 실행 때 다시 해 봐요. 확인 자체가 안 될 때(오프라인 등)는 아무 말도 하지 않아요. 앱은 업데이트하면서 Codex나 다른 앱을 끄지 않아요.

## 지우기

기록 탭 맨 아래의 **앱 지우기**를 눌러요.

1. 누르면 다시 묻지 않아요. 무엇을 하는지는 버튼에 마우스를 올리면 보여요: "연결 설정과 중계기를 되돌리고, Claude Code에 깐 CUA 연결을 지운 뒤 앱이 꺼져요. Codex는 다음에 켤 때부터 연결 없이 원래대로 켜지고, 열린 Claude 대화의 CUA도 끊겨요. Codex가 연결과 함께 켜져 있으면 아무것도 바꾸지 않아요."
2. 누르면 이 순서로 해요. 먼저 Codex 호스트가 켜져 있는지 봐요(켜져 있으면 여기서 멈춰요).
   - Claude Code에서 앱이 깐 `cuabar` MCP(`claude mcp remove -s user cuabar`)를 지워요. Claude Code가 MCP를 지우지 못하면 결과에 `claude mcp remove -s user cuabar`를 직접 하라고 덧붙여요. 0.8.9까지 깐 `cuabar` 스킬은 지우지 않고, 남아 있으면 결과에 `rm -rf ~/.claude/skills/cuabar`를 직접 하라고 덧붙여요(앱은 설정 파일을 고치지 않아요).
   - `codex-cua uninstall`을 돌려요. 연결 설정·중계기·Codex 로그인 설정·`~/.local/bin/codex-cua`를 되돌리고, `~/.local/share/codex-cua`를 엔진 사본과 파이썬 환경까지 통째로 지워요. `codex-cua`가 없거나 이 앱의 것이 아니면 앱에 묶인 엔진 사본의 `setup.sh uninstall`을 대신 돌려요.
   - 앱 자신의 로그인 항목을 풀어요.

   결과를 보여 준 뒤 앱이 꺼져요. 되돌릴 것이 하나도 없었으면 "되돌릴 연결 설정이 없었어요"라고 해요.
3. Codex가 켜져 있어서 되돌릴 수 없으면 "Codex를 정상 종료한 뒤 다시 해 주세요"라고만 하고 아무것도 바꾸지 않아요. 앱은 Codex를 끄지 않아요. Codex 상태를 읽지 못할 때도 아무것도 바꾸지 않고 잠시 뒤 다시 하라고 해요.

**남는 것**은 앱 파일과 아래 넷이에요. 앱 지우기와 `codex-cua uninstall`이 지우지 않는 것이니, 필요 없으면 직접 지워요.

- `~/Library/Caches/codex-cua`: 연결 기록
- `~/Library/Caches/codex-host-cua`: Codex 호스트 상태
- `~/Library/Preferences/dev.chenjing.cua-bar.plist`: 앱 설정
- `~/Library/Application Support/CUABar/Backups/<시각>/CUABar.app`: 업데이트가 남긴 옛 앱 한 벌

앱 파일은 휴지통으로 옮기면 돼요. 앱이 깔지 않은 `cuabar` MCP나 스킬, 옛 플러그인은 앱의 것이 아니라서 건드리지 않고 그대로 있어요.

**앱 파일만 휴지통에 버리면** MCP와 엔진은 그대로 남아서 Claude의 CUA가 계속 쓰이고, 엔진 사본(`~/.local/share/codex-cua`)과 Codex 로그인 설정도 남아요. 이 맥에서 CUA를 치우려면 앱 지우기를 먼저 누르고 그다음에 앱 파일을 버려요.

앱을 꺼도 연결은 그대로 돼요. 앱은 연결이 지나는 길목이 아니라서, 앱을 끄면 상태 보기·자동 정리·잠금 해제 복구·점검·자동 업데이트만 멈춰요. Codex는 앱이 없어도 평소처럼 켜져요.

## 옛 플러그인에서 옮기기

예전에는 Claude 플러그인 `cua@chenjing-plugins`로 깔았어요(회사 마켓플레이스의 `cua@ubion`도 같은 플러그인이에요). 그 플러그인은 마켓플레이스에서 내려갔고, 이제 앱이 그 일을 모두 맡아요. 이미 플러그인을 깔았다면 이렇게 옮겨요.

1. CUA Bar를 깔아서 켜요. 앱은 옛 플러그인을 건드리지 않아요. 점검 탭에 "옛 cua 플러그인이 남아 있어요 — CUA가 둘 붙어요"와 지우는 명령이 보여요.
2. 그 명령으로 옛 플러그인을 지워요: `claude plugin uninstall cua@chenjing-plugins --scope user`(`cua@ubion`이면 `claude plugin uninstall cua@ubion --scope user`)
3. 새 Claude 대화를 열어요. 이제 앱이 깐 MCP만 붙어요.

도구 이름이 `mcp__plugin_cua_cua__js`에서 `mcp__cuabar__js`로(`js_reset`도 같게) 바뀌었어요. 권한 허용 목록이나 훅에 옛 이름을 적어 두었다면 새 이름으로 고쳐요. 0.8.6부터 점검 탭의 허락 규칙 줄이 그런 파일을 찾아 보여 줘요. 옛 이름에 "다시 묻지 않기"로 쌓인 허락은 새 이름에 맞지 않아서 다시 묻기 시작해요. 사용자 설정에 `mcp__cuabar` 한 줄을 더하면(허락 규칙 줄의 복사 버튼) 어느 폴더에서든 다시 묻지 않아요.

0.8.0은 MCP와 스킬을 `cua`라는 이름으로 깔았어요. 0.8.1부터는 이름이 `cuabar`예요(도구는 `mcp__cua__js`에서 `mcp__cuabar__js`로). 0.8.0을 썼다면 새 판이 `cuabar`를 깐 뒤 옛 이름을 지워요: `claude mcp remove -s user cua`, `rm -rf ~/.claude/skills/cua`. 0.8.6부터는 남아 있으면 점검 탭에 그 명령이 보이고(0.8.10부터는 모두 MCP 줄에) 업데이트 알림에도 한 줄이 붙어요. 지우지 않으면 CUA가 둘 붙고, 앱 지우기 뒤에도 옛 `cua` MCP가 없는 파일을 가리킨 채 남아요. 권한 허용 목록이나 훅에 `mcp__cua__`를 적어 두었다면 `mcp__cuabar__`로 고쳐요.

## 개인정보

- 기록과 진단 복사에는 화면, 요청 내용, 시크릿이 들어가지 않아요. 기록에는 시각, 연결, 작업 폴더, 도구 이름, 성공 여부, 걸린 시간만 있고, 진단 복사에는 작업 폴더도 넣지 않아요. 점검 결과도 경로·판·상태 낱말만 넣어요. 이 맥 밖으로 보내지 않아요.
- 앱이 직접 인터넷을 쓰는 곳은 https://cua.chenjing.org 하나예요. 켜질 때와 하루에 한 번 `/version`을 읽고, 새 판이 있을 때만 그 사이트에서 dmg를 받아요. 토큰도 계정도 없이 받고, 보내는 것은 고정된 이름표 하나뿐이에요. 엔진을 설치할 때 필요한 파이썬 패키지(`websockets`)는 엔진의 설치 스크립트가 pip로 받아 와요. 앱은 그 결과의 한 줄 요약만 보여 줘요.
- 앱이 저장하는 것은 업데이트에 실패한 판과 단계와 시각, 이미 알린 판 번호, 메뉴 막대 아이콘 위치, 처음 켰을 때 로그인 항목을 등록했다는 표시뿐이고, `~/Library/Preferences/dev.chenjing.cua-bar.plist`에 있어요. 업데이트를 할 때만 `~/Library/Application Support/CUABar/`에 옛 앱 백업 하나와 "올렸어요" 표시가 생겨요.

## 개발하는 사람에게

```bash
cd apps/cua-bar
swift build && swift test          # 화면이 있는 로그인 세션이 필요해요
./scripts/build-app.sh             # CUABar.app을 만들고 ad-hoc 서명해요. 엔진(engine/)을 번들에 담아요
./scripts/build-app.sh --install   # ~/Applications에 넣어요
CUABAR_NOTARY_PROFILE=<프로필> ./scripts/package-release.sh   # dist/에 서명·공증한 dmg와 SHA256SUMS.txt를 만들어요
./scripts/build-download-site.sh   # dist/의 판으로 download/public/과 download/release.json을 만들어요
(cd download && wrangler deploy)   # cua.chenjing.org에 올려요
```

엔진 시험은 저장소 루트에서 `python3 apps/cua-bar/engine-tests/run.py`와 `node --test apps/cua-bar/engine-tests/relay`로 돌려요([engine-tests/README.md](engine-tests/README.md)). 시험은 CUA를 쓰지 않을 때 돌려요.

- `build-app.sh`는 언제나 hardened runtime으로 서명해서, 손으로 깐 앱도 릴리스와 같은 규칙으로 돌아요. 예외는 Apple Events 하나예요(`scripts/CUABar.entitlements`). Codex 다시 켜기가 osascript로 Codex에 종료를 요청하기 때문이에요. `CUABAR_CODE_SIGN_IDENTITY`를 주면 그 신원으로 서명하고 보안 타임스탬프를 붙여요. 엔진은 서명하기 전에 `CUABar.app/Contents/Resources/engine/`에 담아서 서명이 엔진까지 덮어요(링크와 `__pycache__`·`*.pyc`·`.DS_Store`는 빼요).
- `--install`은 있던 앱과 설정을 `~/Library/Application Support/CUABar/Backups/<시각>/`에 백업하고, 앱이 켜져 있으면 멈추고, 복사본의 서명을 확인한 뒤에 바꿔요.
- 번들로 켠 앱은 개발용 ad hoc 서명이어도 이 맥의 실제 `~/.claude.json`·`~/.local/share/codex-cua`를 바꿔요. `swift run`처럼 번들 밖에서 돈 앱은 엔진도 MCP도 건드리지 않고, 자동 업데이트도 하지 않아요. 번들이어도 ad hoc 서명이면 자동 업데이트를 하지 않아요.
- `package-release.sh [폴더]`는 키체인의 Developer ID Application 인증서로 앱을 만들어요(여럿이면 `CUABAR_CODE_SIGN_IDENTITY`로 골라요). `CUABAR_NOTARY_PROFILE`은 `xcrun notarytool store-credentials`로 만든 프로필 이름이에요. 앱을 공증받아 티켓을 붙이고, 그 앱을 담은 `CUABar-v<판>-macos-arm64.dmg`도 서명·공증해 티켓을 붙인 뒤 `SHA256SUMS.txt`와 함께 폴더에 써요. 기본 폴더는 `apps/cua-bar/dist/`이고 git이 보지 않아요. 체크섬, dmg와 그 안 앱의 서명·티켓, Gatekeeper가 둘 다 받아들이는지까지 확인한 뒤, GitHub 릴리스용 태그 `cua-bar--v<판>`과 실행할 `gh release create ...` 명령을 **출력만** 해요. 태그를 만들거나 올리거나 `gh`를 부르지 않아요. 올리는 것은 그때그때 물어보고 직접 해요. GitHub 릴리스는 선택이에요. 앱의 업데이트와 한 줄 설치는 GitHub를 보지 않아요.
- `download/`는 cua.chenjing.org를 맡는 Cloudflare Worker예요. dmg, `SHA256SUMS.txt`, `install.sh`는 정적 파일로 나가고, `worker.js`가 첫 주소와 `/download`(맥 브라우저는 dmg로 넘기고, 휴대폰·curl 같은 것에는 안내 두 줄), `/install`(에이전트가 읽는 안내), `/version`(`install.sh`와 앱의 자동 업데이트가 읽는 판 정보)을 답해요. `install.sh`는 받은 dmg를 열기 전에(팀만 봐요), 그리고 그 안의 앱을 깔기 전에(번들 ID까지 봐요) 서명 요구 사항(`codesign --verify -R`)으로 검증한 뒤에만 깔아요. `public/`과 `release.json`은 `build-download-site.sh`가 만들고 git이 보지 않아요. 릴리스마다 `package-release.sh` → `build-download-site.sh` → `wrangler deploy` 순서로 올려요(GitHub 릴리스를 올릴 때는 그 사이에 해요). 올리는 것은 그때그때 물어봐요.
- 앱 판 번호는 `engine/.claude-plugin/plugin.json`의 `version`에서 와요(이 파일 이름은 엔진 매니페스트로 그대로 써요). 판을 올릴 때 `engine/host_mcp.py`의 `VERSION`도 같은 값으로 올려요. `engine-tests/test_host_mcp.py`가 둘이 같은지 봐요.
