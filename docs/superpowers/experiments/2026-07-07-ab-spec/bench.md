# A/B spec 벤치 — 인터뷰+게이트의 효용 측정

날짜: 2026-07-07
가설: 인터뷰 + 콜드 리드 게이트가 있는 spec(A안)이, 같은 입력에서 출발한 원샷 spec(B안)보다 맥락 없는 실행자에게 의도를 더 많이 실어 나른다.

## 프로토콜

- **동결 입력**: 아래 문단을 양팔에 동일 제공. 동결 후 수정 금지 (수정하면 B안 재생성).
- **A안 (파이프라인)**: 세션이 `/spec` 인터뷰 수행 → 인터뷰 결정 요약 + 동결 입력을 fresh Opus 서브에이전트에 넘겨 spec 작성 → `/spec-gate` 통과까지 반복.
- **B안 (원샷)**: fresh Opus 서브에이전트가 동결 입력 + 동일 템플릿만으로 1회 작성. 레포 조사 허용, 사용자 접근 금지, 가정 선언·`[NEEDS CLARIFICATION:]` 마커 최대 3개 — `/spec`과 동일 규칙.
- **작성 모델 통제**: 양팔 모두 최종 spec 작성자는 Opus 서브에이전트 (세션 모델의 작문 개입 배제 — 측정 변수를 "인터뷰+게이트 내용물"로 격리).
- **심판**: 우리 게이트를 심판으로 쓰지 않는다 (A안이 게이트 통과까지 반복한 물건이라 순환). 대신 **콜드 구현자 리허설**: 각 spec을 fresh 구현자 서브에이전트에 주고 "구현 착수 전 필요한 질문 목록 + 어쩔 수 없이 찍어야 하는 가정 목록"을 산출시킨다.
- **지표**: ① 착수 전 blocking 질문 수 ② 틀린 가정 수 (사용자 판정) ③ (참고) 각 팔의 spec 제작 총비용(시간·호출 수).
- **예상**: 동결 입력의 "미정" 지점에서 A안 우세. 비기면 논지의 반증으로 정직하게 기록.

## 동결 입력 (양팔 공통)

> Claude Code 플러그인 모음(chenjing-plugins)에 새 플러그인을 추가한다. 목적은 spec 문서가 없는 일상 작업 지대에서 Opus가 "페이블스럽게" — 조용히 갭을 찍고 넘어가지 않게 — 행동하게 만드는 규율 세트다. 3개 층위로 구성한다. ① 항상 켜짐 훅 규율: 세션에 행동 규칙을 주입한다 (찍기 전 실측 조사 — Fable 모방이 아니라 눈치 부족을 정보로 메우는 보상세, 침묵 가정 금지·가정 선언, 요청에 깔린 전제 검증, 선택지 나열 대신 추천+근거로 커밋). ② assume-and-declare 마이크로 아티팩트: 흐릿한 요청을 감지하면 실행 전에 5줄 내외 "작업 계약"(의도 재진술 / 조사로 확인한 것 / 남은 가정 / 완료 기준)을 선언하고, 멈추지 않고 진행한다 — 사용자는 즉시 거부권 행사 가능. ③ 옵트인 답변 게이트 커맨드(이름 후보 /vet): 중요한 질문에 대해 세션이 질문 분해·전제 실측·주장 번호(C-n)를 매긴 초안을 작성하고 → Workflow 스크립트가 렌즈 분산 검증자 3명(전제·사실 / 논리·반례 / 의도 부합)을 병렬 스폰(schema 강제 출력) → 앵커(C-n)+반박 카테고리(enum) 일치 2표 이상만 확정 반박으로 순수 코드 집계 → 세션이 확정 반박을 반영해 수정하고 수정 내역을 투명 표시한다. 제품 주장: "구조화된 Opus ×N은 같은 가격(Fable ≈ Opus ×2)에 검증 가능한 축(확정 오류 수)에서 Fable ×1을 이기고, 검증 불가능한 축(의도 갭)은 사용자 거부권으로 우회한다." 열린 질문용으로 복수 초안 경쟁(best-of-N 선별·합성)도 후보 메커니즘. 기존 fableus 플러그인(spec 지대)과 상호보완 쌍이며 별개 플러그인으로 배포한다. 미정: 플러그인·커맨드 이름, v1에 포함할 층위 범위, 훅 규칙의 정확한 문안과 개수, 작업 계약의 트리거 기준("흐릿한 요청"의 판별)과 강제 방법, 게이트의 수정 후 재검증 정책, 검증자 수·렌즈 구성의 조정 가능성, best-of-N 포함 여부, 성공 기준과 측정 방법.

## 기록

- 2026-07-07: 입력 동결, B안 디스패치, A안 인터뷰 개시.
