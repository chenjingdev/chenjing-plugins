# A/B spec 벤치 — 인터뷰+게이트의 효용 측정

날짜: 2026-07-07
가설: 인터뷰 + 콜드 리드 게이트가 있는 spec(A안)이, 같은 입력에서 출발한 원샷 spec(B안)보다 맥락 없는 실행자에게 의도를 더 많이 실어 나른다.

## 프로토콜

- **동결 입력**: 아래 문단을 양팔에 동일 제공. 동결 후 수정 금지 (수정하면 B안 재생성).
- **A안 (파이프라인)**: 세션이 `/spec` 인터뷰 수행 → 인터뷰 결정 요약 + 동결 입력을 fresh Opus 서브에이전트에 넘겨 spec 작성 → `/spec-gate` 통과까지 반복.
- **B안 (원샷)**: fresh Opus 서브에이전트가 동결 입력 + 동일 템플릿만으로 1회 작성. 레포 조사 허용, 사용자 접근 금지, 가정 선언·`[NEEDS CLARIFICATION:]` 마커 최대 3개 — `/spec`과 동일 규칙.
- **작성 모델 통제**: 양팔 모두 최종 spec 작성자는 Opus 서브에이전트 (세션 모델의 작문 개입 배제 — 측정 변수를 "인터뷰+게이트 내용물"로 격리).
- **심판**: 우리 게이트를 심판으로 쓰지 않는다 (A안이 게이트 통과까지 반복한 물건이라 순환). 대신 **콜드 구현자 리허설**: 각 spec을 fresh 구현자 서브에이전트에 주고 "구현 착수 전 필요한 질문 목록 + 어쩔 수 없이 찍어야 하는 가정 목록"을 산출시킨다.
- **지표**: ① 착수 전 blocking 질문 수 ② 틀린 가정 수 (사용자 판정) ③ (참고) 각 팔의 spec 제작 총비용(시간·호출 수).
- **예상**: 동결 입력의 "미정" 지점에서 A안 우세. 비기면 논지의 반증으로 정직하게 기록.

## 동결 입력 (양팔 공통)

> Claude Code 플러그인 모음(chenjing-plugins)에 새 플러그인을 추가한다. 목적은 spec 문서가 없는 일상 작업 지대에서 Opus가 "페이블스럽게" — 조용히 갭을 찍고 넘어가지 않게 — 행동하게 만드는 규율 세트다. 3개 층위로 구성한다. ① 항상 켜짐 훅 규율: 세션에 행동 규칙을 주입한다 (찍기 전 실측 조사 — Fable 모방이 아니라 눈치 부족을 정보로 메우는 보상세, 침묵 가정 금지·가정 선언, 요청에 깔린 전제 검증, 선택지 나열 대신 추천+근거로 커밋). ② assume-and-declare 마이크로 아티팩트: 흐릿한 요청을 감지하면 실행 전에 5줄 내외 "작업 계약"(의도 재진술 / 조사로 확인한 것 / 남은 가정 / 완료 기준)을 선언하고, 멈추지 않고 진행한다 — 사용자는 즉시 거부권 행사 가능. ③ 옵트인 답변 게이트 커맨드(이름 후보 /vet): 중요한 질문에 대해 세션이 질문 분해·전제 실측·주장 번호(C-n)를 매긴 초안을 작성하고 → Workflow 스크립트가 렌즈 분산 검증자 3명(전제·사실 / 논리·반례 / 의도 부합)을 병렬 스폰(schema 강제 출력) → 앵커(C-n)+반박 카테고리(enum) 일치 2표 이상만 확정 반박으로 순수 코드 집계 → 세션이 확정 반박을 반영해 수정하고 수정 내역을 투명 표시한다. 제품 주장: "구조화된 Opus ×N은 같은 가격(Fable ≈ Opus ×2)에 검증 가능한 축(확정 오류 수)에서 Fable ×1을 이기고, 검증 불가능한 축(의도 갭)은 사용자 거부권으로 우회한다." 열린 질문용으로 복수 초안 경쟁(best-of-N 선별·합성)도 후보 메커니즘. 기존 fableus 플러그인(spec 지대)과 상호보완 쌍이며 별개 플러그인으로 배포한다. 미정: 플러그인·커맨드 이름, v1에 포함할 층위 범위, 훅 규칙의 정확한 문안과 개수, 작업 계약의 트리거 기준("흐릿한 요청"의 판별)과 강제 방법, 게이트의 수정 후 재검증 정책, 검증자 수·렌즈 구성의 조정 가능성, best-of-N 포함 여부, 성공 기준과 측정 방법.

## 기록

- 2026-07-07: 입력 동결, B안 디스패치, A안 인터뷰 개시.

### A안 인터뷰 결정 로그

- I-1 성공 기준: **벤치 + 체감 둘 다** — Fable 접근 소멸 전 확정 오류 수 벤치 1회(게이트 층위) + 2주 후에도 훅·작업 계약을 끄고 싶지 않으면 성공(규율 층위). 기각: 벤치 단독(규율 층위 판정 불가), 체감 단독(제품 주장 미검증 잔존).
- I-2 v1 범위: **3층위 전부** — 층위 1·2는 훅 문안이라 구현비 저렴, 층위 3이 유일한 빌드. 성공 기준 양쪽(벤치=층위 3, 체감=층위 1·2)을 다 재려면 전부 필요. 기각: 층위 3만(체감 판정 불가), 층위 1+2만(Fable 벤치 기회 상실).
- I-3 best-of-N: **v2 백로그** — v1은 반박 게이트 단일 메커니즘으로 고정해 벤치가 가설 하나를 깨끗하게 측정. out-of-scope에 v2 후보로 명기. 기각: v1 포함(벤치 해석 오염), 아예 배제(열린 질문 커버리지 후보를 버림).
- I-4 이름: **플러그인 vet, 커맨드 /vet** — 짧고 동사적, 뜻이 동작과 일치. 기각: fabled(브랜드 분리 불필요), 한국어 브랜드.
- (기록) B안 원샷 spec 완료: FR-001~016, Assumption 12개, 마커 2개(M-1 검증자 도구 접근, M-2 재검증 정책), 소요 약 8.9분 / 78k 토큰 / 도구 12회.
- I-5 작업 계약(층위 2): **항상 켜둠 + 기본 선언, 뻔한 것만 생략** — 생략 조건은 명시적: 짐작할 것이 0개인 요청(대상·할 일·완료 기준이 요청에 전부 명시), 순수 질문·대화 턴. 판별 부담을 "흐린가?"(눈치 필요)가 아니라 "자명한가?"(확인 가능)로 역전. 비용 비대칭 근거: 거짓 양성(불필요한 계약 몇 줄) 싸고 거짓 음성(침묵 오가정) 비쌈. 기각: 흐림 감지 시만(순환), /vet 턴에만(부를 생각을 못 한 턴 = 최위험 턴을 놓침).
- I-6 재검증(층위 3): **수정했을 때만 1회** — 확정 반박 0건이면 즉시 최종(추가 비용 0). 수정 발생 시 1회 재검증으로 수정발(發) 신규 오류를 잡고, 2회차 잔존 반박은 반영 후 미해소 표시하고 종료(루프 없음 — 답변은 spec과 달리 일회성). 기각: 재검증 없음(수정발 오류 무방비), 확정 0까지 반복(과잉).
- I-7 스폰 실패(층위 3): **실패 검증자만 재시도 1회 → 그래도 실패 시 "⚠ 검증 미완료" 배너와 함께 초안 전달** — 답을 삼키지 않고 실패를 숨기지 않음(진행하되 선언 철학과 일관). 기각: 답변 보류(사용자 빈손), 부분 집계 진행(합의 기준이 라운드마다 변동).
- I-8 벤치 설계: **10문항 + 실측 채점** — 정답을 실측 확인 가능한 질문(코드베이스 사실·기술 사실 위주)만 세트에 포함, 채점 = 주장 단위 실측 대조. 우리 게이트 채점(순환)·제3 LLM 채점(산문 채점 회귀) 배격. 체감 술어: 설치 2주 후 훅 활성 유지 + 제거 의사 없음.
- 인터뷰 종료 (질문 8개, 재설명 2회). 잔여 미정(훅 문안·개수, 검증자 수 조정 플래그)은 구현자 재량 + Assumptions로 위임.
- (기록) A안 spec 초판 완료: FR 19개, Assumption 10개, 마커 1개, 소요 약 7.1분 / 77k 토큰 / 도구 15회.
- I-9 검증자 티어 (A안 마커 해소): **Opus 고정 + 가격 문구 정정** — "같은 가격(≈×2)" 슬로건을 "벤치에서 실측 비용 기록으로 사후 보정(예상 Opus ×2~4)"으로 수정. 근거: `CLAUDE_CODE_SUBAGENT_MODEL=opus` 환경변수가 호출별 티어 지정을 덮어써 싼 티어 선택이 실환경에서 무효 + 벤치를 단일 변수(구조 효과)로 유지. 기각: 싼 티어 혼합(환경변수 무효화·이중 변수), 설정 파일 선택(범위 팽창).

- (기록) 게이트 Round 1: 린트 통과 → 리더 3명(폴백 스폰, 전원 tool_uses=0, 5.5~6.4분) → **확정 blocking 1건** (R1-1 벤치 모델 구성 미명시, 2/3표 + 재량 1 수렴) + 단독 blocking 1건(R1-2 검증자 웹 접근, 재량 답 상반) 정보성. 리더 수렴안(초안=Fable)과 사용자 의도(초안=opus)가 갈린 것 자체가 "문서가 의도를 안 실었다"의 실증.
- I-10 벤치 구성 (R1-1 해소): **초안도 opus** — vet arm = opus 초안 + opus 검증 3 vs 기준선 = claude-fable-5 단독 ×1. 제품 주장 그대로 측정(포스트-Fable 실사용 구성). 구조 효과는 부수 지표(초안→최종 오류 감소)로 병행 기록. 기각: 초안=Fable(소멸 후 재현 불가·주장과 상이), 3-arm(비용 1.5배).

- (기록) 게이트 Round 2: 린트 통과 → 리더 3명(전원 tool_uses=0, 4.9~5.6분) → **확정 blocking 1건** (R2-1 벤치 채점 방법론 미조작화, 2/3표 + 재량 1 수렴) + 단독 1건(R2-2 문항 작성 주체, 재량 답 상반) 정보성. R1-1 재제기 없음(해소 확인), R1-2는 재량 3/3 "웹 배제" 수렴으로 종결.
- I-11 채점 규칙 (R2-1 해소): **사전 정답 키 체크리스트** — 문항마다 핵심 사실 목록을 실측 근거와 함께 사전 작성, 채점 = 답변을 항목별 일치/모순/무언급 3분류, 모순만 확정 오류 1건(누락은 오류 아님·별도 기록), 채점 주체 = 저자가 키와 수동 대조(판단 아닌 확인), 정답 키가 분해 기준이라 두 arm 대칭 자동 보장. 기각: 무근거 단정 포함(주관성), 구현자 재량 위임(지표 타당성이 재량에 달림 — 리더 명시 반대).

- (기록) 게이트 Round 3: 린트 통과 → 리더 3명(전원 tool_uses=0, 4.9~5.2분) → **확정 blocking 0건 = passed**. 단독 1건(R3-1 = R2-2 재등장: 벤치 문항 출제 주체, 재량 답 발산) 정보성 — 구현 단계 에스컬레이션 후보로 기록. R2-1(채점 방법론) 재제기 없음.
- **A안 게이트 마감**: `Gate: passed`. 총 3라운드, 확정 blocking 2건(R1-1 벤치 arm 구성, R2-1 채점 방법론) 모두 사용자 채택(I-10, I-11)으로 해소. A안 총비용: 작성자 Opus 4회(초판 7.1분 + 반영 3회) + 콜드 리더 9회(라운드당 ~5분 병렬) + 사용자 결정 11건(I-1~I-11).

### 리허설 공정성 노트

콜드 구현자 리허설 시 두 spec을 중립 경로에 사본으로 만들어 전달한다 — 파일명("oneshot")·frontmatter(Gate 필드 차이)가 팔 정체를 누설하지 않게 frontmatter를 동일 형식으로 정규화.

**질문 내용 대조 (핵심 발견)**:

- **B안 질문 2개 = B spec 자신의 마커 M-1(검증자 도구)·M-2(재검증 정책)** — 둘 다 A안에서는 닫혀 있음(M-2 = I-6 "수정 시 1회 재검증"이 FR-016에 명문화, M-1 = FR-013 "사실 확인용 읽기 외 쓰기 금지" + 게이트 재량 수렴). 원샷 작성자도 진짜 갈림길 위치는 정확히 짚었으나 사용자 없이 닫지 못함 → 구현자 질문으로 그대로 전이. **인터뷰가 산 것 = 이 두 지점의 닫힘.**
- **A안 질문 1개 = 벤치 문항의 출제 도메인·주체** — 게이트가 R2-2/R3-1로 2라운드 연속 기록하고 "구현 단계 에스컬레이션 유력 후보"로 예고한 바로 그 지점. **예고가 적중** — 2표 규칙이 못 막은 단독 이슈가 실제로 표면화됨(거짓 음성 1건의 실측). 단, "에스컬레이션 후보" 기록이 안전망으로 작동해 놀람 없이 수거됨.

**틀린 가정 후보 (사용자 판정 대기)**:

- A-후보1: A안 구현자, 검증자 읽기 도구에 **웹(WebSearch/WebFetch) 포함** — spec 문면은 "사실 확인용 읽기"만 말하고 웹 침묵, 게이트 리더 재량 수렴(3/3)은 웹 배제였음.
