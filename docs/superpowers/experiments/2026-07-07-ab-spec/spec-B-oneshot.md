## User Scenarios & Testing *(mandatory)*

이 플러그인은 3개 층위로 구성되며, 각 층위를 **독립적으로 배포 가능한** 우선순위 스토리로 매핑한다. 각 스토리는 다른 스토리 없이도 단독으로 가치를 전달한다 — 첫 릴리스에 어느 P까지 포함할지(릴리스 컷)는 spec이 고정하지 않고 구현자/사용자 재량에 둔다(D-2, Deferred 참조).

### User Story 1 - 항상 켜짐 규율 주입 (Priority: P1)

사용자가 이 플러그인을 설치한 채 어떤 작업이든 시작하면, 세션 시작 시 행동 규율 규칙이 세션 컨텍스트에 조용히 주입된다. 규칙은 Opus가 (a) 갭을 임의로 찍기 전에 실측 조사를 먼저 하고, (b) 침묵 가정을 금하고 가정을 선언하며, (c) 요청에 깔린 전제를 검증하고, (d) 선택지 나열 대신 추천+근거로 커밋하도록 유도한다.

**Why this priority**: 세 층위 중 가장 저렴하고 기반적이다. 다른 층위 없이 이 층위만 있어도 세션마다 행동 규율이 걸려 가치를 전달한다. 기존 fableus 플러그인이 이미 `SessionStart` 훅으로 규칙을 주입하는 선례가 있어(`plugins/fableus/hooks/hooks.json:8`) 관례가 확립돼 있다.

**Independent Test**: 플러그인만 설치한 새 세션을 시작해, 세션 컨텍스트에 규율 규칙 텍스트(4개 행동 축 전부)가 주입됐는지 확인한다. 다른 층위 미구현 상태로도 통과 가능하다.

**Acceptance Scenarios**:

1. **Given** 플러그인만 설치된 상태, **When** 새 세션을 시작하면, **Then** 세션 컨텍스트에 4개 행동 축(실측 조사·가정 선언·전제 검증·추천 커밋)을 담은 규율 규칙이 주입된다.
2. **Given** 규칙이 주입된 세션, **When** 사용자가 근거 없이 갈림길이 있는 요청을 하면, **Then** 세션은 임의로 찍지 않고 실측 조사 또는 가정 선언(US2/규칙에 따른 행동)으로 대응한다.

### User Story 2 - 흐릿한 요청의 작업 계약 선언 (Priority: P2)

세션이 들어온 요청을 "흐릿하다"고 판단하면, 요청에 실제로 작용하는 첫 도구 사용 이전에 5줄 내외의 "작업 계약"을 출력한다. 계약은 정확히 네 슬롯을 가진다: 의도 재진술 / 조사로 확인한 것 / 남은 가정 / 완료 기준. 계약을 출력한 뒤 세션은 **멈추지 않고 진행**하며, 사용자는 즉시 거부권을 행사할 수 있다.

**Why this priority**: 규율(US1)을 관찰 가능한 아티팩트로 물질화한다. "조용히 갭 찍기"를 계약 선언으로 막되, 진행을 차단하지 않아 마찰이 낮다. US1 위에서 가장 큰 행동 변화를 만든다.

**Independent Test**: 흐릿함 라벨이 붙은 요청 집합을 던져, 첫 도구 사용 이전에 네 슬롯을 모두 채운 계약이 트랜스크립트에 출력되고, 출력 후 세션이 대기 없이 진행하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 규칙이 주입된 세션, **When** 흐릿한 요청이 들어오면, **Then** 요청에 작용하는 첫 도구 사용 전에 4슬롯 계약이 출력된다.
2. **Given** 계약이 출력된 직후, **When** 추가 사용자 입력이 없으면, **Then** 세션은 멈추지 않고 계약대로 진행한다.
3. **Given** 계약 출력 직후, **When** 사용자가 계약의 특정 슬롯(예: 남은 가정)을 거부하면, **Then** 세션은 진행을 중단하고 거부된 지점을 반영한다.

### User Story 3 - 중요 질문의 답변 게이트 (/vet) (Priority: P3)

사용자가 중요한 질문에 대해 옵트인 커맨드(/vet)를 호출하면, 세션이 질문을 하위 질문으로 분해하고 전제를 실측한 뒤 주장마다 번호(C-n)를 매긴 초안을 작성한다. Workflow 스크립트가 렌즈가 다른 검증자 3명(전제·사실 / 논리·반례 / 의도 부합)을 병렬로 스폰하고, 각 검증자는 스키마를 강제한 반박을 낸다. 앵커(C-n)와 반박 카테고리(enum)가 일치하며 2표 이상인 반박만 "확정 반박"으로 순수 코드가 집계한다. 세션은 확정 반박을 반영해 초안을 수정하고, 수정 내역을 투명하게 표시한다.

**Why this priority**: 제품의 핵심 주장("구조화된 Opus ×N은 같은 가격에 검증 가능한 축=확정 오류 수에서 Fable ×1을 이긴다")을 실현하는 층위지만, Workflow 스크립트·이종 검증자·스키마 강제 집계로 가장 복잡하다. 옵트인이므로 미구현이어도 US1/US2의 상시 규율은 온전하다.

**Independent Test**: 논리·사실·의도 부적합 오류를 K개 심은 벤치마크 답변에 /vet를 실행해, 확정 반박(2표 이상)으로 ≥K개를 포착하고, 수정 내역 표시에 각 확정 반박이 어떤 C-n을 어떻게 바꿨는지 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 /vet를 호출, **When** 세션이 초안을 작성하면, **Then** 초안은 하위 질문 분해·실측한 전제·번호 매긴 주장(C-n)을 포함한다.
2. **Given** C-n이 매겨진 초안, **When** Workflow 스크립트가 검증자를 스폰하면, **Then** 정확히 3명이 병렬 스폰되고 각자 렌즈에 배정된다.
3. **Given** 검증자 3명의 스키마 준수 출력, **When** 순수 코드가 집계하면, **Then** (동일 C-n 앵커 AND 동일 카테고리 enum)을 2인 이상이 제기한 항목만 확정 반박으로 계수된다.
4. **Given** 확정 반박 N건, **When** 세션이 수정하면, **Then** 각 확정 반박을 반영한 수정과 변경 로그(어떤 C-n을 왜 바꿨는가)가 표시된다.
5. **Given** 확정 반박 0건, **When** 집계가 끝나면, **Then** 초안이 그대로 확정되고 변경 로그에 "변경 없음"이 표시된다.

### Edge Cases

- **흐릿함 오탐/미탐**: Layer 2는 소프트(진행 비차단)이므로 오탐 시 불필요한 계약이 나오지만 진행을 막지 않으며 사용자가 무시할 수 있고, 미탐 시 계약이 누락된다(허용 — 하드 게이트가 아니다, D-4). 정확도 문턱을 통과 조건으로 삼지 않는다.
- **검증자 스폰 실패**: 한 명이라도 스폰 실패 또는 스키마 위반 출력 시, /vet 실행을 중단하고 실패 사실만 보고하며 부분 집계를 기록하지 않는다(fableus 선례: `plugins/fableus/skills/spec-gate/SKILL.md:49-50`).
- **확정 반박 간 상충**: 두 확정 반박이 모순된 수정을 요구하면, 세션은 상충을 명시적으로 표시하고 한쪽을 채택한 근거를 변경 로그에 남긴다(무단 선택 금지).
- **best-of-N 요청**: 복수 초안 경쟁/합성은 v1 범위 밖이며(D-10), 요청 시 범위 밖임을 안내한다.
- **/vet 대상이 코드가 아니라 자연어 답변**: 앵커는 파일:라인이나 FR 번호가 아니라 초안의 주장 번호(C-n)다. fableus 게이트의 앵커=FR/섹션과 대비되는 이 층위의 앵커 축이다.
- **초안이 컨텍스트 한도 초과**: /vet는 분할 없이 거부하고 질문 축소를 권고한다(fableus 선례: `plugins/fableus/skills/spec-gate/SKILL.md:26` 크기 상한 거부 패턴).

## Requirements *(mandatory)*

### Functional Requirements

**Layer 1 — 항상 켜짐 훅 규율**

- **FR-001**: 플러그인은 `SessionStart` 훅을 등록해, 매 세션 시작 시 규율 규칙 텍스트를 세션 컨텍스트에 주입해야 한다(MUST). 주입 메커니즘은 fableus 선례와 동일한 `additionalContext` 방식이다(`plugins/fableus/hooks/hooks.json:8` — `hookSpecificOutput.hookEventName=SessionStart` + `additionalContext`). 규칙은 최소한 다음 4개 행동 축을 인코딩해야 한다: (a) 갭을 찍기 전 실측 조사(눈치 부족을 정보로 메우는 보상세), (b) 침묵 가정 금지·가정 선언, (c) 요청에 깔린 전제 검증, (d) 선택지 나열 대신 추천+근거로 커밋. **정확한 문안과 규칙 개수는 구현자 재량(값)이며, 위 4개 축의 포함은 필수(축)다.**
- **FR-002**: Layer 1 주입은 비대화식이어야 하고 세션 시작에 차단 단계를 추가하지 않아야 한다(MUST) — 훅은 `additionalContext`만 방출한다. (fableus·resume 훅 모두 세션 시작을 차단하지 않는 command 훅이다: `plugins/fableus/hooks/hooks.json:3-11`, `plugins/resume/hooks/hooks.json:37-47`.)

**Layer 2 — assume-and-declare 마이크로 아티팩트**

- **FR-003**: 세션이 들어온 요청을 "흐릿하다"고 판단하면(판별 = 모델의 자가 평가, 주입된 관찰 가능 휴리스틱 기준; 휴리스틱의 구체 목록 = 구현자 재량), **요청에 실제로 작용하는 첫 도구 사용 이전에** 정확히 네 슬롯을 가진 작업 계약을 출력해야 한다(MUST): ① 의도 재진술 ② 조사로 확인한 것 ③ 남은 가정 ④ 완료 기준. 분량은 5줄 내외(정확한 상한은 구현자 재량).
- **FR-004**: 계약 출력 후 세션은 멈추지 않고 진행해야 하며(MUST, 비차단), 사용자는 즉시 거부권을 행사할 수 있어야 한다(MUST). 계약은 **행동적 규율**이며 Layer 1이 주입/강화하는 것이지, 구조적 하드 게이트가 아니다 — 해당 하네스에서 "흐릿한 요청"을 어시스턴트의 미방출 자연어 응답 단계에서 의미적으로 차단하는 훅 이벤트가 없기 때문이다(D-4).
- **FR-005**: 계약의 "남은 가정" 슬롯은 Layer 1의 "가정 선언" 규칙과 일관되어야 한다(MUST) — 가정은 침묵하지 않고 표면화한다.

**Layer 3 — 옵트인 답변 게이트 (/vet)**

- **FR-006**: 플러그인은 사용자가 명시적으로 호출하는 옵트인 커맨드(작업명 /vet)를 제공해야 한다(MUST). "중요한 질문"의 판단은 사용자 몫이며, 이 커맨드는 수동 호출이고 Layer 1·2가 자동 트리거하지 않는다(경계: 검증자 스폰은 오직 명시적 /vet 뒤에서만 일어난다).
- **FR-007**: /vet 호출 시 세션은 (a) 질문을 하위 질문으로 분해하고, (b) 전제를 실측하며, (c) 주장마다 번호 C-n을 매긴 초안을 작성해야 한다(MUST).
- **FR-008**: Workflow 스크립트가 검증자 3명을 병렬로 스폰해야 한다(MUST). 각 검증자는 서로 다른 렌즈를 배정받는다: 전제·사실 / 논리·반례 / 의도 부합. 검증자는 초안 내용을 프롬프트에 직접 받아야 하며(파일 경로 전달 금지 — 격리, fableus 선례 `plugins/fableus/skills/spec-gate/SKILL.md:45-46`), 스키마를 준수하는 출력을 내야 한다(스키마 강제 프롬프트의 선례: `plugins/fableus/skills/spec-gate/references/reader-prompt.md:8-43`). 검증자 서브에이전트는 fableus `cold-reader`와 같은 검사 전용 에이전트 형태다(`plugins/fableus/agents/cold-reader.md` — 인사말·후기 없이 기계 처리용 본문만 출력).
- **FR-009**: 각 검증자 반박은 앵커(대상 주장 C-n)와 반박 카테고리(닫힌 enum, 코드 비교 가능)를 필수로 태깅해야 한다(MUST). **enum의 구체 멤버 = 구현자 재량(값)**이나, enum은 세 렌즈의 실패 유형(전제·사실 오류 / 논리·반례 / 의도 부적합)을 구분할 수 있어야 한다(축).
- **FR-010**: **확정 반박 = 동일 (C-n 앵커, 카테고리 enum)을 2인 이상이 제기한 것**이며, 순수 코드가 집계해야 한다(MUST) — 집계에 별도 LLM 심판을 두지 않는다(fableus 선례 D-10: `plugins/fableus/skills/spec-gate/SKILL.md:52-61` 앵커 기반 기계 합산 + LLM 심판 금지). 1인 단독 반박은 정보성으로만 표시하고 확정에서 제외한다.
- **FR-011**: 검증자 전원 성공을 요구해야 한다(MUST) — 한 명이라도 스폰 실패 또는 스키마 위반 출력 시, /vet 실행을 중단하고 부분 집계를 기록하지 않는다(fableus 선례: `plugins/fableus/skills/spec-gate/SKILL.md:49-50`).
- **FR-012**: 세션은 모든 확정 반박을 반영해 초안을 수정해야 하며(MUST), 어떤 C-n이 어떤 확정 반박을 반영해 어떻게 바뀌었는지 투명한 변경 로그를 표시해야 한다(MUST). 수정은 자율적이다(반박별 사용자 게이트 없음) — 사용자는 수정된 답변 전체에 거부권을 가진다. (fableus 게이트가 blocking마다 사용자에게 되묻는 것과 대비되는 이 층위의 자율 수정 축이며, 근거는 아이디어 원문 "세션이 확정 반박을 반영해 수정하고 수정 내역을 투명 표시한다"이다.)
- **FR-013**: 수정 후 재검증 정책 — [NEEDS CLARIFICATION M-2: 확정 반박을 반영해 수정한 초안에 대해 검증자를 다시 돌려 수렴(확정 반박 0건)까지 자율 루프를 돌 것인가, 아니면 단일 패스로 끝내고 재검증은 사용자의 수동 /vet 재호출로만 할 것인가? 근거 양쪽 존재: 단일 패스는 비용·지연을 한정하고 아이디어 원문이 단일 수정 단계를 기술한다; 자율 루프는 fableus의 "확정 blocking 0건까지 반복"(SKILL.md:26, D-9) 수렴 보장을 재현하고 /vet는 자율 수정이라 사용자 피로 없이 루프 가능하다.] 잠정 기본값: **단일 패스**(자동 재실행 없음), /vet 재호출은 수동.
- **FR-014**: 검증자의 도구·네트워크 접근 — [NEEDS CLARIFICATION M-1: 전제·사실 렌즈 검증자에게 도구/네트워크 접근을 주어 세계에 대한 라이브 사실 검증(실측)을 하게 할 것인가, 아니면 fableus `cold-reader`처럼 도구 없이(`tools: []`, `plugins/fableus/agents/cold-reader.md:4`) 초안의 진술된 전제·내부 정합성만 검사하게 할 것인가? 이는 /vet가 잡아내는 "확정 오류"가 무엇인지를 좌우한다 — 도구 없으면 내부 모순·진술 전제 오류만, 도구 있으면 사실 오류까지. 양쪽 근거 존재: 아이디어의 "전제 실측"은 도구 쪽을, 격리·재현성·순수 코드 집계·보안 표면 축소는 도구 없음 쪽을 가리킨다.] 잠정 기본값: **도구 없는 검증자**(내부 정합성 + 진술 전제 검사) + **실측은 초안 작성 세션이 초안 시점에 자신의 도구로 수행**.

**교차 관심사**

- **FR-016**: best-of-N(복수 초안 경쟁·best-of-N 선별·합성)은 v1 범위 밖이다(D-10).

### Key Entities

- **DisciplineRuleset (Layer 1)**: 세션에 주입되는 행동 규율 규칙 묶음. 필수 속성 = 4개 행동 축(실측 조사·가정 선언·전제 검증·추천 커밋)의 표현. 문안·개수는 값.
- **WorkContract (Layer 2)**: 흐릿한 요청 감지 시 출력하는 마이크로 아티팩트. 정확히 네 슬롯(의도 재진술 / 조사 확인 / 남은 가정 / 완료 기준). 상태: 출력됨 → (사용자 거부 시) 중단·반영 / (무입력 시) 진행.
- **Draft (Layer 3)**: /vet가 만든 답변 초안. 속성 = 하위 질문 분해, 실측한 전제, 번호 매긴 주장 목록 C-n.
- **ValidatorReport (Layer 3)**: 검증자 1명의 스키마 준수 출력. 반박 목록을 포함하며, 각 반박은 (앵커 C-n, 카테고리 enum, 논지 요약)로 태깅. 렌즈 식별자를 가진다.
- **ConfirmedRebuttal (Layer 3)**: (앵커 C-n, 카테고리 enum, 지지 검증자 수 ≥2). 순수 코드 집계의 산물.
- **RevisionChangelog (Layer 3)**: 어떤 C-n이 어떤 ConfirmedRebuttal을 반영해 어떻게 바뀌었는지의 투명 기록. 확정 반박 0건이면 "변경 없음".

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 논리·사실·의도 부적합 오류를 K개 심은 벤치마크 답변에 /vet를 실행하면, 확정 반박(2표 이상)으로 ≥K개를 포착한다.
- **SC-002**: 모든 확정 반박이 (동일 C-n 앵커, 동일 카테고리 enum, 지지 검증자 ≥2)를 만족함을 집계 아티팩트 검사로 확인할 수 있다 — 확정 반박 판정에 LLM 심판이 개입하지 않는다(순수 코드).
- **SC-003**: 흐릿함 라벨이 붙은 요청 R건에서, 세션이 요청에 작용하는 첫 도구 사용 이전에 4슬롯(의도 재진술/조사 확인/남은 가정/완료 기준)을 모두 채운 작업 계약을 트랜스크립트에 출력한다.
- **SC-004**: 플러그인이 설치된 모든 세션 시작에서 규율 규칙이 세션 컨텍스트에 주입된다(`additionalContext` 존재로 관찰 가능).
- **SC-005**: /vet 1회 실행이 정확히 3명의 검증자를 스폰하며(비용 축 = 고정 N으로 검사 가능), 검증자 중 1명이라도 스키마 위반 출력을 내면 부분 집계 없이 실행이 중단된다.
- **SC-006** *(제품 주장 · 사후 검증 · 하네스는 납품 범위 밖)*: 동일 씨앗-오류 벤치마크에서 /vet(Opus 초안 + 검증자 3)가 포착한 확정 반박 수 ≥ Fable 단일 패스가 같은 벤치마크에서 포착한 수. 벤치마크·A/B 비교 하네스는 산출물 범위에 포함되지 않는다(D-11) — SC는 작성/검증 세션의 사후 기준이다.

- **Workflow 집계 스크립트의 구현 언어·파일 구조**: 구현자 재량. 사유: resume가 Node `.mjs` 스크립트를 `${CLAUDE_PLUGIN_ROOT}` 참조로 훅에서 호출하는 선례(`plugins/resume/hooks/hooks.json:9`)가 있으나 언어 강제는 값이다. 순수 코드 집계(축, FR-010)만 고정.

## Assumptions

- 이 플러그인은 Claude Code 환경(서브에이전트 스폰·훅 등록 가능)에서 동작한다.
- 산출물 문서(plugin.json/marketplace 설명·SKILL 등)의 기본 언어는 한국어다 — 레포의 모든 기존 `plugin.json`·`marketplace.json` 설명이 한국어다(`.claude-plugin/marketplace.json:3,10,18,26`).
- Layer 1은 fableus와 동일한 `SessionStart` + `additionalContext` 주입 방식을 쓴다(비차단, `plugins/fableus/hooks/hooks.json:8`). 두 플러그인이 함께 설치되면 규칙 주입이 중첩될 수 있으나 상호보완적이라 충돌로 보지 않는다.
- Layer 2 계약 강제는 소프트(행동적)이며 진행을 차단하지 않는다(D-4). "흐릿함" 판별은 모델 자가 평가다(D-5).
- /vet는 수동 옵트인이며 "중요한 질문" 판단은 사용자 몫이다. Layer 1·2가 /vet를 자동 트리거하지 않는다.
- /vet 검증자는 3명·3고정 렌즈·2-of-3 합의이며(D-6), fableus 기본값(리더 3 / 2인 이상 합의, `plugins/fableus/skills/spec-gate/SKILL.md:16,62`)과 정렬한다.
- 집계는 순수 코드, 검증자 출력은 스키마 강제, 전원 성공-또는-중단이다(D-7·D-8).
- 확정 반박 반영·수정은 자율 + 투명 변경 로그다(D-9).
- best-of-N은 v1 범위 밖(D-10), SC 벤치마크·하네스는 납품 범위 밖(D-11)이다.
- (잠정, M-1 대기) 검증자는 기본 도구 없음이며 실측은 초안 세션이 초안 시점에 수행한다.
- (잠정, M-2 대기) 수정 후 재검증은 단일 패스이며 /vet 재호출은 수동이다.
- /vet 대상 초안은 단일 세션 컨텍스트에 들어가는 크기다(초과 시 거부·축소 권고).
