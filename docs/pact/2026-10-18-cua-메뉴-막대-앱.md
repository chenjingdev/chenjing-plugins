# CUA 메뉴 막대 앱
## 목적
Codex를 평소처럼 켜도 Claude가 CUA로 바로 붙게 하고, 메뉴 막대에서 상태를 보고, AI가 정리 없이 끝나며 남긴 브라우저 점유를 풀어 다음 연결이 막히지 않게 한다.
## 범위
회사 맥의 cua 0.6.0(자동 연결)과 Portwarden의 CUA 기능(연결 목록·종료·놓아주기·중계기)을 떼어 agent-bar 같은 macOS 메뉴 막대 앱 하나로 다시 만든다. 체크리스트 25개가 모두 이번 판이다.
## 하지 않는 것
- Codex 없이 혼자 도는 CUA, Codex의 모델·권한·승인 설정 바꾸기, cmux-cua 설정 바꾸기, macOS 밖의 운영체제.
## 기능
- F1 Codex를 Dock·Spotlight·업데이트 뒤 재실행 등 평소처럼 켜도 Claude가 바로 붙고, 꺼져 있으면 Claude 대화를 열 때 뒤에서 켠다(대화를 여는 것이 곧 쓰는 것이라 따로 고르는 스위치는 없다). 앱은 로그인할 때 자동으로 뜬다 [사용자]
  - 케이스: 앱이나 플러그인이 깨짐 → Codex는 연결 없이 원래대로 켜지고 아이콘이 문제로 바뀐다
  - 케이스: Codex가 연결 없이 켜져 있음 → 끄지 않고 "하던 Codex 작업이 끊긴다"를 적은 알림으로 다시 켤지 묻고, 누르면 정상 종료(강제 종료 없음) 뒤 다시 켠다
- F2 아이콘 하나로 준비·문제·작업 중을 구분하고, 올리면 한 줄 요약 툴팁, 누르면 연결 목록과 놓아주기·종료 메뉴가 열린다. 문제마다 다음에 할 일 한 줄과 고치는 버튼이 있다 [사용자]
- F3 브라우저 점유를 연결 하나씩, 또는 끝난 연결 것만 한 번에 놓아준다. 주인이 사라진 점유는 세션 ID로 콕 집어 푼다 [사용자]
  - 케이스: 콕 집어 풀기가 안 됨 → 확장 초기화 방법과 함께, 초기화하면 끊길 살아 있는 연결 목록을 보인다
- F4 Claude·Codex 연결 목록(작업 폴더, 시작 시각, 메모리, 살아 있는지, 오래 쉬는지)과 정상·강제·묶음 종료(전체·Claude만·Codex만). 끄기 전에 탭을 놓아준다. 이 기능은 Portwarden에서 빼서 옮기고, 원래 작업은 브랜치로 남긴다 [사용자]
  - 케이스: 놓아주기에 실패한 채 강제 종료됨 → 남은 점유를 F3의 주인 없는 점유로 보인다
- F5 AI가 정리 없이 끝나면 앱이 대신 점유를 놓아주고, 점유가 오래 남으면 알린다 [사용자]
- F6 cmux-cua 같은 다른 도구 상태, 지금 어느 AI가 화면·포커스를 쓰는지, 최근 조작 기록과 진단 복사 버튼을 한 곳에 보인다 [사용자]
- F7 agent-bar처럼 GitHub Releases에서 받고, 앱에서 Claude 플러그인을 설치·갱신하고, 새 버전을 알린다 [사용자]
## 공통 규칙
- R1 앱은 사용자가 누르기 전에는 Codex·Chrome·AI를 끄지 않고, 어떤 창도 앞으로 끌어오지 않는다 — 하던 작업과 포커스를 지키려고 [AI 가정]
- R2 기록과 진단 복사에는 화면, 요청 내용, 시크릿을 넣지 않고 이 맥 밖으로 보내지 않는다 — 기존 cua 플러그인 규칙 [AI 가정]
- R3 앱을 지워도 Codex는 깨지지 않고 원래대로 켜지며, 메뉴의 제거는 연결 설정과 중계기까지 되돌린다 — 앱이 사라진 뒤 Codex가 못 켜지는 일이 없게 [AI 가정]

<details><summary>그 밖의 AI 가정 19개</summary>

- R4 앱은 chenjing-plugins 저장소에 cua 플러그인과 같이 두고 같은 판 번호로, 0.7.0부터 낸다. 짓기는 origin/main에서 새 worktree로 하고, main의 커밋 안 된 baton·pact 변경은 건드리지 않는다 — 앱과 플러그인 판이 어긋나지 않고, 회사 맥의 커밋 안 된 0.6.0과 판 번호가 겹치지 않게 [AI 가정]
- R5 회사 맥의 0.6.0은 ssh로 읽기만 하고 회사 맥에서는 아무것도 바꾸지 않는다. 닿지 않으면 0.6.0의 세 동작을 처음부터 짓는다. 0.6.0 시험 때 깔린 LaunchAgent(com.chenjingdev.codex-cua.env)가 있으면 앱이 이어받는다 — 회사 맥의 작업을 지키려고 [AI 가정]
- R6 앱 이름은 가칭 CUA Bar다. agent-bar처럼 ad-hoc 서명만 하고 공증은 하지 않으며, Apple Silicon·macOS 14 이상이다 — 이름은 나중에 바꿔도 기능이 같고, 배포는 agent-bar와 같게 [AI 가정]
- R7 앱을 꺼도 연결은 그대로 되고, 상태 보기와 자동 정리만 멈춘다 — 앱이 연결의 길목이 되지 않게 [AI 가정]
- R8 연결은 그것을 쓰는 AI 대화로 가른다. Claude 대화가 Codex 안에 띄운 런타임과 메모리는 Claude 연결에 붙고 "Codex만"으로 끄지 않는다. "끝난 연결"은 AI 대화가 사라졌는데 런타임이 남은 것, "주인 없는 점유"는 연결까지 사라졌는데 Chrome에 남은 점유다. 대화가 살아 있으면 오래 쉬어도 끝난 것이 아니다 — 일하는 중인 AI의 탭을 놓지 않게 [AI 가정]
- R9 세션 ID로 콕 집어 풀기는 앱만 하고, AI가 부르는 도구로는 열지 않는다. 앱이나 플러그인이 직접 기록한 세션 가운데 주인이 사라진 것만 푼다. 주인을 모르는 점유는 "주인 모름"으로 보이고 저절로 풀지 않는다. 예전 규칙("남의 세션 ID로 정리하지 않는다", "MCP를 켤 때 Codex를 켜지 않는다")은 F1·F3에 필요한 만큼만 바꾼다 — 살아 있는 대화의 탭을 잘못 풀지 않게 [AI 가정]
- R10 놓아주기는 AI가 정상 종료 때 하는 원래 정리(turn_ended)와 같다. AI가 만든 임시 탭은 닫히고, 사용자 탭과 넘겨주려고 남긴 탭은 그대로 둔다 — 원래 동작을 그대로 쓰려고 [AI 가정]
- R11 Codex 대화의 탭을 끄기 전에 놓는 중계기도 Portwarden에서 옮긴다. 앱을 처음 켤 때 한 번 묻고, ~/.codex/config.toml을 백업한 뒤 깔고, 제거 때 되돌린다. 중계기는 앱 번들 밖에 두고, 플러그인에 박힌 Portwarden 경로(host_mcp.py, portwarden_control.py)는 앱 쪽 경로로 바꾼다. Codex가 갱신되면 설정을 다시 맞추고, 못 맞추면 원래 설정으로 돌리고 문제로 보인다 — 중계기가 없으면 Codex 연결은 끄기 전에 탭을 못 놓고, 작업 중·쉼·세션 ID도 모른다 [AI 가정]
- R12 Codex가 꺼졌다 켜지면(갱신 포함) 열린 Claude 대화는 다음 호출 때 새 호스트에 다시 붙는다. 끊길 때 하던 조작은 되풀이하지 않는다 — Codex가 갱신될 때마다 열린 대화가 모두 CUA를 잃지 않게 [AI 가정]
- R13 아이콘은 문제 > 작업 중 > 준비 순으로 하나만 보인다. Codex가 꺼져 있어도 Claude 대화를 열 때 켤 수 있으면 준비다. 작업 중은 최근 10초 안에 CUA 호출이 있었던 때다. 문제와 고치는 버튼: 연결 없이 켜진 Codex(다시 켜기), 끝난 연결·주인 없는 점유(놓아주기), 플러그인 없음·판 다름(설치·갱신), 래퍼·중계기 깨짐(고치기), Codex 없음(받는 곳 열기) — 문제를 놓치지 않고, Codex를 꺼 두는 것만으로 문제가 되지 않게 [AI 가정]
- R14 점유 목록을 못 읽으면 정리가 확인되지 않은 채 끝난 연결을 "점유가 남았을 수 있음"으로 보이고, 개수는 쓰지 않는다. 오래 남은 점유 알림도 이것으로 센다 — 못 읽는다고 아무것도 안 보이는 일이 없게 [AI 가정]
- R15 놓아주기가 거절되면(도구 호출이 아직 끝나지 않음) 한 번 더 묻고, 그래도 안 되면 "작업이 끝나지 않아 못 놓음"과 다시 하기·강제 종료를 보인다. 정상 종료는 그대로 끄고, 플러그인이 끝날 때 한 번 더 놓는다. 그래도 확인되지 않으면 주인 없는 점유로 보인다 — 하던 조작을 끊지 않게 [AI 가정]
- R16 오래 쉬는 연결은 30분 넘게 CUA 호출이 없는 연결이고, 기록이 없으면 "알 수 없음"이다. 오래 남은 점유는 주인이 사라진 뒤 1분 넘게 안 풀린 점유이고, 알림은 점유마다 한 번이다 — 10/11처럼 쉬는 런타임이 메모리를 잡는 걸 보고, 대신 놓아주기가 실패한 것만 알리려고 [AI 가정]
- R17 묶음 종료와 강제 종료는 몇 개를 끄는지 보이고 한 번 묻는다. 묶음 종료는 Claude·Codex CUA 연결만이고, cmux-cua 연결은 하나씩 끈다 — 되돌릴 수 없고, 다른 도구를 한꺼번에 끊지 않게 [AI 가정]
- R18 조작 기록은 플러그인과 중계기가 새로 남긴다. 시각·연결·도구 이름·성공 여부·걸린 시간만 최근 200개 남기고, js의 제목과 코드는 넣지 않는다 — 진단에는 충분하고 내용은 남지 않게 [AI 가정]
- R19 새 버전은 하루 한 번 이 저장소의 앱 태그로 확인한다. 플러그인은 cua@chenjing-plugins 이름으로 깔고, 앱과 판이 다르면 문제로 보이고 맞는 판 받기를 고치는 버튼으로 둔다. 갱신하면 새 Claude 대화부터 새 판이 붙는다고 알린다 — 마켓플레이스가 저절로 갱신돼 플러그인이 앱보다 먼저 바뀔 수 있어서 [AI 가정]
- R20 Portwarden의 커밋 안 된 변경은 통째로 백업 브랜치에 남기고, main 작업 트리에서는 CUA 부분만 걷어 낸다. 같이 섞인 "프로젝트 폴더 묶기" 작업은 커밋하지 않은 채 그대로 둔다 — 다른 작업이 사라지거나 main에 섞여 커밋되지 않게 [AI 가정]
- R21 연결·점유·다른 도구가 없으면 탭마다 "없음" 한 줄을 보이고, 알림이 꺼져 있으면 아이콘과 상태 카드에만 보인다. 다른 도구는 지금은 cmux-cua 하나다 — 빈 화면이 고장처럼 보이지 않게 [AI 가정]
- R22 GitHub push와 Release는 할 때마다 묻는다 — 두 저장소 모두 공개라 되돌리기 어렵다 [AI 가정]

## 구조 판정
B 팝오버(`.pact/cua-메뉴-막대-앱/sketches/B.html`): 맨 위 상태 카드와 고치기 버튼, 아래 탭(연결 / 브라우저 점유 / 다른 도구 / 기록), 줄마다 놓아주기·종료 버튼. 세 안의 기능이 같아 추천안 B로 AI가 정했다.
## 확인 필요
- 점유 목록을 읽고 주인 없는 점유를 세션 ID로 푸는 방법은 실제 Chrome에서 아직 확인 전이다. 안 되면 F3은 확장 초기화 안내만, F5의 대신 놓아주기는 알림만 남는다. build 처음에 확인한다.
- F6의 "누가 화면·포커스를 쓰나"는 도구가 남기는 기록만큼만 보인다. 짐작: Claude 연결은 보이고, Codex 자체 연결과 cmux-cua는 build에서 확인한다.## 결정 기록
