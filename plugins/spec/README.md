# spec (v0.2.0)

러프한 아이디어를 인터뷰로 파고들어 실행 모델이 문서만으로 구현할 수 있는 명세(SPEC.md)로 만들고, 독립 콜드 리더의 병렬 읽기로 그 명세를 측정하는 관문까지 — 작성과 검증을 한 쌍으로 묶은 플러그인.

| 명령 | 하는 일 |
|---|---|
| `/spec:spec` | 러프한 아이디어를 인터뷰로 파고들어 구현 가능한 명세(SPEC.md)로 만든다. 완성되면 관문이 자동 발동 |
| `/spec:spec-gate` | 콜드 리더 N명(기본 3, 무맥락·무도구)을 워크플로우 하나로 병렬 실행 — 출력은 schema로 강제, 2표 이상 겹침(앵커+범주 일치)은 스크립트가 셈. 확정 0이면 통과, 아니면 피드백 반영 후 다음 라운드 자동 시작 |

**출력 위치**: `/spec`은 프로젝트 루트에 `SPEC.md` 하나만 만든다 — 커밋되는 단일 원천이며, `specs/NNN-slug/` 번호 디렉터리는 더 이상 쓰지 않는다. 대시보드·게이트 리포트 같은 도구 상태는 루트의 `.spec/`에 두며, 이 디렉터리는 `*` 한 줄짜리 `.spec/.gitignore`로 스스로를 무시해 그 안의 무엇도 커밋되지 않는다(사용자의 루트 .gitignore는 건드리지 않는다). 이미 `SPEC.md`가 있으면 충돌이 아니라 개정 입력으로 삼는다 — 무시하고 새로 쓰는 건 명시적 확인이 있을 때만.

- salvo와의 관계: spec-gate는 메커니즘상 vote 병합 측정(독립 판독 N개를 코드가 2표 이상으로 집계)이며, 나중에 salvo 플랫폼의 preset으로 재등록될 예정이다. 지금은 별개 제품이라 독립 플러그인으로 분리했다.
