# salvo (v0.9.0)

salvo는 플러그인에 동봉된 하위 스킬로 요청을 라우팅하는 단일 문(`/salvo`)이다 — 라우팅 카드를 실시간 스캔해 맞는 하위 스킬로 보내고, 매칭이 없으면 내장 엔진이 처리한다. 하위 스킬이 아무리 늘어도 세션 컨텍스트에는 이 문 하나만 올라가고, 유저는 뭐가 있는지 몰라도 된다.
내장 엔진은 같은 요청을 여러 번 독립 실행하고 그 결과를 코드로 병합한다 — 한 번의 실행은 짐작에 그치지만, 독립 실행 여러 개를 코드로 합치면 측정이 된다. 메인 세션은 실행을 배치하는 오케스트레이션만 맡고, 병합·집계·표 세기 같은 판독은 전부 코드와 워크플로우가 수행한다.

병렬 실행 플랫폼(`SPEC.md`, 게이트 통과 — 통과 증적은 `docs/003-*`)이 존재하며, 이전 프리셋은 그 위에 재등록될 예정이다:

| 명령 | 하는 일 |
|---|---|
| `/salvo:salvo` | 단일 문. 라우팅 카드를 실시간 스캔해 맞는 하위 스킬로 라우팅(run preset → 폼 실행 / 절차형 하위 스킬 → 지시 수행). 매칭이 없으면 내장 엔진: 즉석 폼 작성(union/vote/pick 병합, 표 세기는 코드), 위임(1회 실행 = "단일 실행 — 교차 검증 없음"), 못 채우면 반려. 실행 기록은 ~/.claude/plugins/data/salvo-chenjing-plugins/records/에 축적 (승격 증거) |

- 인터뷰 명세 작성 + 콜드 리더 관문은 v0.8.0에서 별도 `spec` 플러그인으로 분리되었고(breaking), v0.8.2부터 두 플러그인은 완전 별개다 — 이 문은 스펙 요청을 특별 취급하지 않고 여느 작업처럼 폼으로 처리하며, 다른 플러그인을 호출·언급하지 않는다 (D-10).
- 상시 주입 훅은 없다 (의도적으로 뺌 — 이름과 훅은 세션을 조건화하는 토큰이므로).
- 이전 프리셋(vet · sweep · leg)과 새 프리셋(분할 · 갈림 감지 · 평문 인계 등)은
