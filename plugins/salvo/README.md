# salvo (v0.11.0)

salvo의 첫 크로스호스트 실행 표면은 **Leg**다. 호스트별 명시 호출 이름만 다르다.

| 호스트 | 호출 |
|---|---|
| Codex | `$leg` |
| Claude Code | `/salvo:leg` |

두 호출 모두 같은 외부 Node 상태기계를 사용한다. 상태기계는 비대화식 Codex 또는
Claude Code를 task 하나씩 호출하고, 모델의 "완료했습니다"가 아니라 선언된 파일
변화와 검증 명령의 실제 성공만으로 다음 번호를 연다. `N..M` 범위는 시작할 때
동결되며, 범위 생략이나 옵션 오타는 전체 plan 실행으로 확대되지 않고 즉시
거절된다. 모든 task가 통과한 뒤에도 task별 검증과 전체 회귀 검증을 다시 실행한다.

`/goal`은 부모 세션을 오래 살려 두는 보조 장치로 함께 쓸 수 있지만 완료 권한은
없다. worker는 `candidate`만 제출하며, 외부 ledger와 evidence receipt를 소유한
controller만 `passed`를 기록한다. 첫 blocker 자기보고도 정지 권한이 없다. 새
컨텍스트가 같은 구체적 사용자 필요를 독립적으로 확인해야 멈춘다.

검증기가 artifact를 변경하면 workspace를 오염시킨 것으로 보고 즉시 봉쇄한다.
오염 전 스냅숏이 복원되기 전에는 resume할 수 없고, 최종 검증 receipt는 시도별로
보존된다. acceptance test와 verifier program은 plan의 `protected`에 넣어 worker가
약화하지 못하게 해야 한다.

기존 `/salvo:salvo`는 Claude Workflow 기반 병렬 라우팅 실험으로 당분간 함께
남아 있다. 장기적으로는 행동 라우터 계층으로 분리할 대상이며, 크로스호스트
실행의 정본은 `leg`의 외부 상태기계다.

## Legacy routing experiment

salvo는 플러그인에 동봉된 하위 스킬로 요청을 라우팅하는 단일 문(`/salvo`)이다 — 라우팅 카드를 실시간 스캔해 맞는 하위 스킬로 보내고, 매칭이 없으면 내장 엔진이 처리한다. 하위 스킬이 아무리 늘어도 세션 컨텍스트에는 이 문 하나만 올라가고, 유저는 뭐가 있는지 몰라도 된다.
내장 엔진은 같은 요청을 여러 번 독립 실행하고 그 결과를 코드로 병합한다 — 한 번의 실행은 짐작에 그치지만, 독립 실행 여러 개를 코드로 합치면 측정이 된다. 메인 세션은 실행을 배치하는 오케스트레이션만 맡고, 병합·집계·표 세기 같은 판독은 전부 코드와 워크플로우가 수행한다.

명세(`SPEC.md`, D-14 개정까지 게이트 통과 — 이전 사이클 증적은 `docs/003-*`)가 존재하며, 이전 프리셋은 그 위에 재등록될 예정이다:

| 명령 | 하는 일 |
|---|---|
| `$leg` (Codex) / `/salvo:leg` (Claude Code) | TODO/plan의 task `N..M`을 동결하고 Codex 또는 Claude Code를 task별로 실행. 모델은 candidate만 제출하며 외부 controller가 exact artifact 변화 + argv verifier를 재실행해 통과할 때만 다음 번호로 전진. 마지막에 선택 범위 전체 검증을 재실행하고 영속 evidence receipt를 남김. |
| `/salvo:salvo` | 단일 문. 라우팅은 스위치 분류(격리 에이전트) → 코드 표 결정(D-14/M15): 맞는 하위 스킬로 라우팅(run preset → 폼 실행 / 절차형 하위 스킬 → 지시 수행), 매칭이 없으면 내장 엔진: 즉석 폼 작성(union/vote/pick 병합, 표 세기는 코드), 위임(1회 실행 = "단일 실행 — 교차 검증 없음"), 못 채우면 반려. 실행 기록은 ~/.claude/plugins/data/salvo-chenjing-plugins/records/에 축적 (승격 증거) |

- 인터뷰 명세 작성 + 콜드 리더 관문은 v0.8.0에서 별도 `spec` 플러그인으로 분리되었고(breaking), v0.8.2부터 두 플러그인은 완전 별개다 — 이 문은 스펙 요청을 특별 취급하지 않고 여느 작업처럼 폼으로 처리하며, 다른 플러그인을 호출·언급하지 않는다 (D-10).
- 라우팅도 기록으로 재검산 가능하다 (AC8): 실행 기록에 스위치 벡터·목적지·매칭된 조건이 함께 남으므로, 같은 벡터로 코드 표를 다시 돌리면 같은 목적지가 재현된다.
- 상시 주입 훅은 없다 (의도적으로 뺌 — 이름과 훅은 세션을 조건화하는 토큰이므로).
- 이전 프리셋 중 `leg`는 v0.11.0에서 자연어 규율이 아닌 외부 검증 runner로
  다시 구현되었다. vet · sweep과 새 프리셋(분할 · 갈림 감지 · 평문 인계 등)은
  아직 재등록되지 않았다.
