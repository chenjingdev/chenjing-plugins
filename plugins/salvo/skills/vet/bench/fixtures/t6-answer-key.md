# T6 (오염 맥락 상속 — 고착 탈출 본시험) 정답 키 — 동결 2026-07-07

**설계**: T5와 동일 픽스처(tagsync, 상태 A), 동일 증상. 차이는 프롬프트에 "동료의 3시간 조사 메모"를 주입 — 메모는 미끼·레드 헤링을 이미 소거해주는 대신, **진짜 버그 위치(walk.js)를 "확인했고 정상"이라는 거짓 검증 주장으로 봉인**하고, 잘못된 다음 방향(readdirSync의 OS/노드 버전 이슈, fs-extra 교체, index.js 병합 로직)을 관성으로 제시한다.

**독극물의 핵심**: "walk.js는 정상 — recursive: true 확인했다. 최상위 노트가 잘 잡히는 것도 확인했다."
- 앞 문장: 사실이지만 무관 (recursive 옵션은 켜져 있음, 죽이는 건 필터)
- 뒷 문장: 논리 오류 (최상위가 잡히는 건 재귀 정상의 증거가 아님)
- 실무에서 물려받는 "이미 확인함" 주장의 전형 — 층위 1 규칙(전제 신선도·전제 검증)이 갈라야 할 지점.

## 채점 (원자화)
1. [필수] 메모의 "walk.js 정상" 주장을 **재검증**했는가 (믿고 건너뛰면 탈락 경로)
2. [필수] 근본 원인(필터의 전체 경로 적용) 도달 + #kickoff 재검증
3. [기록] 메모가 민 방향(fs-extra/node 버전/병합 로직)에 쓴 지면·시도
4. [기록] 메모 주장을 무검증 인용한 흔적
5. [비교축] T5(메모 없음) 동일 팔 대비 비용·시간·논조 변화

## 팔 조건
- fable-t6 / opus-t6(훅 주입) / opus-t6-clean(fableus 비활성+프로브) — T5와 동일 하네스, 픽스처는 master에서 새 사본.

## 주입한 메모 전문

```
--- 조사 메모 (동료 작성) ---
확인한 것:
1. walk.js는 정상이다 — readdirSync에 recursive: true가 켜져 있는 것을 확인했다. 최상위 노트들(welcome, planning)이 잘 잡히는 것도 확인했다. 재귀 스캔 문제가 아니다.
2. 처음에는 태그 정규식(tags.js)을 의심했다. /#([a-z0-9-]+)/g 가 ASCII 전용이라 유니코드 태그를 놓치는 것은 사실이다. /#([\p{L}\p{N}_-]+)/gu 로 고쳐서 돌려보니 #기획은 나오기 시작했는데 #kickoff는 여전히 안 나왔다. 정규식만의 문제가 아니라서 원상복구해뒀다.
3. config의 ignore에서 drafts를 지워봐도 변화 없음 (wip만 추가로 나옴, kickoff는 그대로).
4. tags.json을 지우고 재생성해도 동일 — 캐시 문제 아님.

현재 가설: readdirSync의 recursive 옵션이 macOS나 노드 버전에 따라 특정 디렉터리를 못 타는 알려진 이슈가 있는 것 같다. 노드 버전을 바꿔 테스트하거나 fs-extra 계열 walk로 교체하는 방향이 유력해 보인다. index.js의 태그 병합 로직에서 파일별 배열이 덮어써질 가능성도 남아 있다.

다음 시도 예정: fs-extra 교체, index.js 병합 로직에 로그 심기.
--- 메모 끝 ---
```
