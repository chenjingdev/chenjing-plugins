# 런이 끊기는 방식과 대처

끊긴 런은 셋 중 하나로 채운다. 우선순위와 결과에 남길 각주가 다르다.

1. **같은 조건 재실행** — 처음부터 다시. 각주: "1차 시도가 X로 중단돼 재실행".
2. **세션 재개** — 하네스의 resume 기능으로 같은 대화를 이어 같은 앱 상태에서 계속. 각주: "X로 중단(N노트) 후 같은 세션 재개".
3. **새 지시** — 대화형으로 열어 부족한 점을 지시. 원샷 벤치가 아니게 되므로 각주에 지시 원문을 남긴다.

사용자가 "이어서"라고 하면 2를 먼저, 안 되면 3. 어느 쪽이든 앱 상태를 **같은 인스턴스**에서 이어야 한다.

## Claude 사용량 한도 — `You've hit your session limit · resets 4pm`

화면에 이 한 줄이 찍히고 종료된다. 리셋 시각 전에는 어떤 재시도도 같은 줄로 끝난다. 시각이 지나면:

- 재실행이면 그냥 다시 보낸다.
- 재개는 `--resume <세션ID>`. 세션 ID는 `~/.bench/_claude/projects/…/` 안에서 런 태그를 grep해 찾은 파일명. 앱이 aria면 그 런의 인스턴스에 다시 붙어야 하므로 프로필의 `claude-mcp.json`을 복사해 `ARIA_DATA_DIR`를 **그 런의 세션 디렉터리**로, `ARIA_DATA_DIR_PER_SESSION`을 `"0"`으로 바꾼 일회용 설정을 만든다. 세션 디렉터리는 포트로 찾지 말고 **살아 있는 pid**로 찾는다. 죽은 인스턴스의 runtime.json에 같은 포트가 남아 있어 잘못 짚은 적이 있다.
  ```
  cd ~/.bench/aria/work && CLAUDE_CONFIG_DIR=~/.bench/_claude claude --resume <id> --strict-mcp-config --mcp-config <일회용.json> --permission-mode bypassPermissions --model fable --effort xhigh -p "세션 한도로 중단됐었다. 현재 곡 상태를 확인하고 이어서 완성해 줘. …"
  ```
- 한도 시각을 알면 CronCreate로 그 시각에 재실행을 예약할 수 있다.

## agy print 모드 5분 타임아웃 — `Error: timeout waiting for response`

러너 0.4.0부터 `--print-timeout 2h`를 넣어 해결됐다. 옛 러너로 돌렸다면 BENCH_MJS로 새 러너를 지정해 재실행.

## 모델이 빈 응답 — `Agent execution terminated due to error`, `model output must contain either output text or tool calls`

모델 쪽 문제다. 한 번은 재실행하고, 다시 나면 그 모델은 대화형 TUI로 넘어간다(같은 프롬프트를 한 줄로 직접 입력). 세 번째 시도까지 안 되면 "미완주"로 기록하는 것이 맞다. 결과 없이 재시도만 반복하는 것도 시간 낭비지만, 실패 자체가 벤치 결과라는 점을 사용자에게 말한다.

## 모델이 실행 대신 계획만 서술 — "…/plan 명령을 쓰세요"

print 모드에서 슬래시 명령을 권하며 사용자에게 돌려보내는 경우. 대화형 TUI로 열어 같은 프롬프트를 넣으면 진행한다. 각주에 "대화형" 표시.

## 결과가 프롬프트 조건을 무시 — 8마디짜리 "3분 곡", 비어 있는 트랙

원샷 결과로는 그대로 기록한다(그것이 결과다). 사용자가 채우길 원하면 새 지시를 한 번만 넣고 지시 원문을 각주에 남긴다.

## 모델의 보고가 사실과 다름 — "MP3로 내보냈다"

파일이 없고 앱 편집 이력에 export가 없다. 모델 말을 믿지 말고 결과물은 파일 존재로 확인한다. 필요하면 벤치 측에서 앱 API로 렌더하고 파일명·각주에 "내보내기는 벤치 측"이라고 적는다.

## 보내기 자체가 잘못됨

잘못된 워크스페이스(인덱스 해석)나 잘못된 데이터 디렉터리로 시작했으면 몇 초 안에 멈추는 것이 맞다. 프로세스를 죽이고 그 런이 만든 빈 인스턴스가 있으면 함께 내린다.
