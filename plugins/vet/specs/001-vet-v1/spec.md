## User Scenarios & Testing *(mandatory)*

### User Story 1 - /vet 답변 게이트로 중요한 질문의 확정 오류를 깎는다 (Priority: P1)

사용자가 코드베이스·기술 사실이 걸린 중요한 질문에 `/vet <질문>`을 건다. 세션은
질문을 분해하고 전제를 실측한 뒤 각 주장에 `C-n` 앵커를 붙인 초안을 만든다.
Workflow 스크립트가 렌즈가 서로 다른 검증자 3명(전제·사실 / 논리·반례 / 의도
부합)을 병렬 스폰하고, 순수 코드가 앵커+카테고리 일치 2표 이상만 확정 반박으로
집계한다. 세션은 확정 반박만 반영해 초안을 고치고, 무엇을 왜 고쳤는지 수정
내역을 투명하게 보여준다.

**Why this priority**: 3층위 중 유일하게 실제로 "빌드"되는 부분이고, 성공
기준의 벤치 축(Fable 접근 소멸 전 확정 오류 수, I-1·I-8)이 정확히 이 층위를
잰다. 이것 하나만 있어도 "중요한 질문 1건을 검증 가능한 축에서 개선한다"는
독립 가치가 나온다.

**Independent Test**: 벤치 10문항 중 1문항에 `/vet`를 걸어, 초안 대비 최종
답변의 실측 오류 수가 줄거나 같은지(그리고 확정 반박이 수정 내역에 1:1로
드러나는지)를 관찰해 검증한다.

**Acceptance Scenarios**:

1. **Given** 실측 가능한 전제가 걸린 질문, **When** `/vet`를 실행하고 검증자
   2명 이상이 같은 `C-n`을 같은 반박 카테고리로 지목, **Then** 세션은 해당
   `C-n`을 수정하고 수정 내역(어느 C-n이 어떤 확정 반박으로 바뀌었는지)을 표시한다.
2. **Given** 검증자 중 1명만 어떤 `C-n`을 반박, **When** 집계, **Then** 그
   반박은 정보성으로만 표시되고 초안 수정을 강제하지 않는다.
3. **Given** 확정 반박 0건, **When** 집계 완료, **Then** 초안이 즉시 최종이
   되며 재검증을 돌리지 않는다(추가 검증자 호출 0).

### User Story 2 - 작업 계약으로 침묵 오가정을 드러낸다 (Priority: P2)

사용자가 spec 없는 일상 작업(대상·할 일·완료 기준이 요청에 다 담기지 않은
요청)을 시킨다. 세션은 실행에 앞서 5줄 내외의 "작업 계약"(의도 재진술 / 조사로
확인한 것 / 남은 가정 / 완료 기준)을 선언하고, 멈추지 않고 바로 진행한다.
사용자는 계약이 틀렸으면 즉시 개입해 거부할 수 있다.

**Why this priority**: 벤치로는 못 재지만 성공 기준의 체감 축(설치 2주 후 끄고
싶지 않음, I-1)을 지탱한다. 훅 문안이라 구현비가 싸고, 층위 1 위에서 동작한다.

**Independent Test**: 완료 기준이 명시 안 된 요청을 주고, 실행 전에 4개 필드를
채운 계약이 선언되는지 / 자명한 요청(대상·할 일·완료 기준 전부 명시 또는 순수
질문)에는 계약이 생략되는지를 관찰한다.

**Acceptance Scenarios**:

1. **Given** 완료 기준이 요청에 없는 작업, **When** 세션이 실행을 시작, **Then**
   실행 전에 의도 재진술·조사 확인·남은 가정·완료 기준 4필드가 선언된다.
2. **Given** 대상·할 일·완료 기준이 요청에 전부 명시된 자명한 작업, **When**
   실행, **Then** 계약을 생략하고 바로 진행한다.
3. **Given** 순수 질문·대화 턴, **When** 응답, **Then** 계약을 선언하지 않는다.

### User Story 3 - 항상 켜진 훅이 세션에 행동 규율을 심는다 (Priority: P3)

플러그인을 설치하면 세션 시작마다 행동 규칙이 자동 주입된다: 찍기 전 실측 조사,
침묵 가정 금지·가정 선언, 요청에 깔린 전제 검증, 선택지 나열 대신 추천+근거로
커밋. 사용자가 아무것도 안 해도 켜져 있다.

**Why this priority**: 층위 2·3이 딛는 토대이자 체감 성공 기준의 판정 대상(2주
후 이 훅을 끄고 싶은가). 문안 주입이라 구현비가 가장 싸다.

**Independent Test**: 새 세션을 열어 주입된 컨텍스트에 네 규율이 관찰 가능한
문장으로 들어있는지, 옵트인 없이 매 세션 켜지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플러그인 설치, **When** 새 세션 시작, **Then** 네 규율이 세션
   컨텍스트에 주입된다(사용자 조작 불필요).

### Edge Cases

- **렌즈 분산 vs 합의 투표의 긴장**: 검증자 3명은 일부러 렌즈가 다르므로 같은
  `C-n`에 2표가 모이기 어렵다. 이때 확정 반박 0건 → 초안이 최종이 된다(설계상
  의도). 이 긴장은 리스크로 인지하되 확정 결정(렌즈 분산 + 2표 합의)을 그대로
  따른다 — 카테고리 enum을 세 렌즈가 공유해 교차-렌즈 합의가 표현 가능하게 한다.
- **검증자 전원 실패(재시도 후에도)**: 부분 집계로 진행하지 않고(라운드마다
  합의 기준이 변동하는 것을 금지) "⚠ 검증 미완료" 배너와 함께 초안을 전달한다.
- **수정이 새 오류를 유발**: 수정 발생 시 1회 재검증이 수정발 신규 오류를
  잡는다. 재검증에서도 남는 확정 반박은 반영 후 "미해소"로 표시하고 종료한다
  (루프 없음 — 답변은 일회성).
- **자명 판별 오분류**: 자명한 요청을 흐린 것으로 오분류하면 불필요한 계약 몇 줄
  (거짓 양성, 저비용). 흐린 요청에 계약을 생략하면 침묵 오가정(거짓 음성,
  고비용) — 판별 술어를 "흐린가?"가 아니라 "자명한가?"로 두어 고비용 오류를 줄인다.
- **파괴적·비가역 작업**: 작업 계약은 기존 Claude Code 권한 시스템을 우회하지
  않는다. 계약 선언 + 기존 권한 프롬프트가 함께 거부 창을 준다.
- **벤치 문항의 정답이 다툼거리**: 실측 확인 불가능한 문항은 세트에서 제외한다
  (I-8 — 정답을 실측 확인 가능한 질문만 포함).
- **고위험 턴에 `/vet`를 부를 생각을 못 함**: 층위 3은 옵트인이라 이 턴을 못
  잡는다. 층위 1·2가 그 안전망이다(3층위를 모두 배포하는 근거).

## Requirements *(mandatory)*

### Functional Requirements

**패키징**

- **FR-001**: 시스템은 `vet` 이름의 플러그인을 루트 `.claude-plugin/marketplace.json`
  의 `plugins` 배열에 `fableus`와 **별개** 항목으로 MUST 등록한다. 항목 형태는
  기존 항목(`name`/`description`/`source`/`skills`)을 따른다
  (근거: `/Users/chenjing/dev/chenjing-plugins/.claude-plugin/marketplace.json`).
- **FR-002**: 시스템은 `plugins/vet/.claude-plugin/plugin.json`을 기존
  plugin.json 형태(`name`·`description`·`version`)로 MUST 제공하며 `name`은
  `vet`이다 (근거: `plugins/fableus/.claude-plugin/plugin.json`,
  `plugins/tiers/.claude-plugin/plugin.json`).

**층위 1 — 항상 켜짐 훅 규율**

- **FR-003**: 시스템은 세션 행동 규칙을 SessionStart 훅의
  `hookSpecificOutput.additionalContext`로 MUST 주입한다. 훅은
  `plugins/vet/hooks/hooks.json`에서 자동 발견되며(plugin.json에 훅 참조 불필요),
  fableus의 SessionStart 패턴을 따른다
  (근거: `plugins/fableus/hooks/hooks.json:3-13`).
- **FR-004**: 주입 규칙은 최소한 네 규율을 관찰 가능한 문장으로 MUST 포함한다:
  (a) 사실 주장을 찍기 전 실측 조사, (b) 침묵 가정 금지 — 가정했으면 산출물에
  선언, (c) 요청에 깔린 전제를 행동 전에 검증, (d) 선택지 나열 대신 추천 1개 +
  근거로 커밋. **정확한 문안과 규칙 개수는 구현자 재량**.
- **FR-005**: 훅은 매 SessionStart에 MUST 발화하며(항상 켜짐) 사용자 옵트인을
  MUST NOT 요구한다.

**층위 2 — assume-and-declare 작업 계약**

- **FR-006**: 자명하지 않은 요청을 실행하기 전에 세션은 5줄 내외의 작업 계약을
  MUST 선언하며, 계약은 정확히 네 필드를 담는다: 의도 재진술 / 조사로 확인한 것 /
  남은 가정 / 완료 기준. (필드 순서·포맷은 구현자 재량.)
- **FR-007**: 작업 계약은 기본 켜짐·기본 선언이며, **생략은 요청이 자명할 때만**
  MUST 한다. "자명함"은 관찰 가능한 술어로 정의한다: 요청이 대상 AND 할 일 AND
  완료 기준을 이미 전부 명시(짐작할 것 0개) — 또는 순수 질문·대화 턴(수행할
  동작 없음) (근거: I-5).
- **FR-008**: 계약 선언 후 세션은 확인을 기다리지 않고 MUST 진행한다(사용자는
  개입으로 즉시 거부권을 행사) (근거: I-5).
- **FR-009**: 파괴적·비가역 작업은 기존 Claude Code 권한 시스템으로 계속
  게이트되며, 작업 계약은 이를 MUST NOT 우회한다.

**층위 3 — 옵트인 /vet 답변 게이트**

- **FR-010**: 시스템은 옵트인 커맨드 `/vet`(스킬 `vet`)를 MUST 노출하며 사용자
  명시 호출로만 발동된다. 게이트의 자동 발동은 MUST NOT 존재한다 (근거: I-4,
  옵트인).
- **FR-011**: `/vet <질문>` 시 세션은 (a) 질문을 분해하고 (b) 전제를 실측하며
  (c) 각 원자 주장에 안정적 앵커 `C-n`을 붙인 초안을 MUST 만든다. (C-n 포맷
  세부는 구현자 재량.) 초안 생성 모델은 **일상 사용에서는 세션 모델**(사용자
  세션이 sonnet이든 opus든 그 모델이 초안을 씀) — Fable 소멸 후 실사용 구성과
  동일하다. **벤치에서만 초안 모델을 opus로 고정**한다(FR-018·I-10).
- **FR-012**: Workflow 스크립트(`Workflow({scriptPath, args})`로 호출되는 엔진)가
  렌즈 분산 검증자 **정확히 3명**을 병렬 MUST 스폰한다: 렌즈 A = 전제·사실,
  렌즈 B = 논리·반례, 렌즈 C = 의도 부합. 각 검증자는 schema 강제 구조화 출력을
  MUST 낸다 (근거: `plugins/tiers/skills/deep-research/engine.js:90-98,279-289`;
  Workflow scriptPath 관례: `plugins/tiers/skills/deep-research/SKILL.md:10`).
- **FR-013**: 각 검증자는 모든 반박을 특정 `C-n`에 MUST 앵커링하고 **세 렌즈가
  공유하는 반박 카테고리 enum** 값으로 라벨링한다(교차-렌즈 합의가 표현
  가능하도록 카테고리는 렌즈 간 동일). 검증자는 MUST 격리한다: 초안 본문을
  프롬프트에 직접 담아 전달하고(파일 경로 금지), 사실 확인용 읽기 외 저장소·도구
  쓰기 접근을 주지 않는다 (근거: `plugins/fableus/skills/spec-gate/SKILL.md:41-51`;
  2축 라벨·앵커 필수: `plugins/fableus/skills/spec-gate/references/reader-prompt.md:8-18`).
- **FR-014**: 집계는 **순수 코드**로 MUST 한다(LLM 심판 없음). 확정 반박 = 검증자
  2명 이상이 같은 `C-n`을 지목 AND 같은 카테고리 enum 값에 일치. 1인 단독 반박과
  앵커/카테고리 불일치는 정보성일 뿐 확정으로 승격되지 MUST NOT 된다
  (근거: `plugins/fableus/skills/spec-gate/SKILL.md:52-63`;
  순수 코드 투표 집계: `plugins/tiers/skills/deep-research/engine.js:40-43,296-306`).
- **FR-015**: 세션은 모든 확정 반박을 반영해 초안을 MUST 수정하고, 어느 `C-n`이
  어떤 확정 반박으로 바뀌었는지 수정 내역을 MUST 투명 표시한다. 확정되지 않은
  반박은 수정을 강제하지 MUST NOT 한다.
- **FR-016**: 확정 반박이 1건 이상이라 수정이 발생하면 게이트는 정확히 1회
  재검증을 MUST 한다. 확정 반박 0건이면 초안이 즉시 최종이며 추가 검증 비용은
  0이다. 재검증에서도 남는 확정 반박은 반영 후 "미해소"로 표시하고 게이트를 MUST
  종료한다(추가 루프 없음 — 답변은 spec과 달리 일회성) (근거: I-6).
- **FR-017**: 검증자 스폰·반환 실패 시 게이트는 실패한 검증자만 1회 MUST
  재시도한다. 재시도 후에도 실패하면 게이트는 답변을 보류하거나 부분 집계로
  진행하지 않고 "⚠ 검증 미완료" 배너와 함께 초안을 MUST 전달한다(합의 기준이
  라운드마다 변동하지 않도록) (근거: I-7; 인프라 실패와 반박을 구분하는 선례:
  `plugins/tiers/skills/deep-research/engine.js:296-302,320-328`).

**벤치 (성공 기준 실측 장치)**

- **FR-018**: 시스템은 층위 3 벤치를 MUST 제공한다: 정답을 실측 확인 가능한
  질문(코드베이스 사실·기술 사실 위주) **10문항**의 고정 세트. 각 문항은 작성
  시점에 **핵심 사실 체크리스트(정답 키)**를 실측 근거(파일:라인 또는 출처)와
  함께 사전 작성한다. **채점 방법론**(I-11): 각 arm의 답변을 정답 키 항목별로
  **일치 / 모순 / 무언급** 3분류하고, **모순 항목 수 = 그 답변의 확정 오류 수**로
  센다. 무언급(누락)은 오류가 아니며 별도 기록한다. 채점 주체는 **저자가 정답 키와
  수동 대조**한다(판단이 아니라 확인). 정답 키가 주장 분해 기준이므로 vet 답
  (C-n 있음)과 기준선 답(산문)에 **동일하게 적용**된다 — 분해 주관성을 정답 키가
  흡수한다. vet 자신의 검증자로 채점(순환)하거나 제3 LLM 산문 채점은 MUST NOT
  쓴다 (근거: I-8·I-11). 벤치는 정확히
  두 arm을 MUST 비교한다: **vet arm = opus 초안 + opus 검증자 3(전 과정 opus,
  수정 시 opus 재검증 3)** vs **기준선 = claude-fable-5 단독 ×1(세션 모델 단독
  1회 응답, 게이트 없음)**. 이 주 비교는 의도적 시스템 대 시스템 비교다. 벤치는
  각 `/vet` 실행의 비용(모델 호출 구성: 초안 1 + 검증 3 + 수정 시 재검증 3, 예상
  Opus ×2~4)을 실측 기록해 제품 주장을 사후 보정하는 데이터로 MUST 남긴다 —
  "같은 가격" 슬로건 대신 실측 비용을 정본으로 삼는다 (근거: I-9). **부수 지표**:
  각 벤치 문항에서 vet 내부의 초안 오류 수 → 최종 오류 수 감소량(delta)을 게이트
  자체의 기여 측정으로 MUST 병행 기록한다 (근거: I-10).

**범위 밖 (음성 요구)**

- **FR-019**: 복수 초안 경쟁(best-of-N 선별·합성)은 v1에 MUST NOT 구현한다. v2
  백로그 후보로 기록한다 (근거: I-3 — 벤치가 반박 게이트 단일 가설을 깨끗하게
  측정하도록).

### Key Entities *(데이터를 다루는 기능이면 포함)*

- **작업 계약(Work Contract)**: 자명하지 않은 요청 실행 직전에 선언되는 5줄 내외
  아티팩트. 필드: 의도 재진술 / 조사로 확인한 것 / 남은 가정 / 완료 기준. 영속화
  없음(대화 턴에만 존재).
- **초안 주장(Claim, C-n)**: `/vet` 초안 안의 원자 주장. 안정적 앵커 `C-n`으로
  식별되며 검증자·집계·수정 내역이 모두 이 앵커로 참조한다.
- **검증자 반박(Verdict)**: 검증자 1명의 구조화 출력 단위. 앵커(`C-n`) + 반박
  카테고리(공유 enum) + 근거를 담는다. 확정 반박 = 같은 앵커+카테고리에 2표 이상.
- **벤치 세트(Bench Set)**: 실측 확인 가능한 10문항. 각 문항은 **핵심 사실
  체크리스트(정답 키)** — 실측 근거(파일:라인 또는 출처)를 붙인 정답 항목 목록 —
  를 구성 요소로 갖는다. 채점은 답변을 정답 키 항목별로 일치/모순/무언급 3분류하고
  모순 수만 확정 오류로 센다(무언급 별도 기록). 두 arm을 비교한다 — **vet arm**
  (opus 초안 + opus 검증자 3) vs **기준선/Fable**. 이 spec에서 **"Fable" = 기준선
  모델 `claude-fable-5`의 세션 모델 단독 1회 응답(게이트 없음)**을 뜻하는 정의된
  용어다.

## Success Criteria *(mandatory)*

  변수를 늘리지 않으려 opus로 통일한다(주 비교는 시스템 대 시스템 — I-10/D-14).
- **벤치 arm 구성** (I-10): vet arm = opus 초안 + opus 검증자 3(전 과정 opus),
  기준선 = `claude-fable-5` 단독 ×1(게이트 없음). 일상 사용의 초안 모델은 세션
  모델이지만 벤치에서만 초안을 opus로 고정한다.
- **재검증(FR-016)**은 수정된 전체 초안에 대해 검증자 3명을 1회 전면 재실행한다
  (수정발 신규 오류는 어느 주장에서든 발생할 수 있으므로 델타 검증이 아님).
- **/vet 답변은 일회성**이다 — 대화 턴에만 존재하며 파일로 영속화하지 않는다
  (spec과 달리, I-6 "일회성").
- **층위 2 거부권**은 사용자 개입(interrupt)으로 행사되며, 파괴적 작업은 기존
  권한 시스템이 계속 막는다(신규 거부 도구 없음, FR-009).
- **주입/UI 문안 언어 = 한국어** (기존 플러그인 관례).
- **벤치는 저자가 Fable 접근 소멸 전 수동 1회 실행**하고 결과를 보고한다(자동
  CI 아님, I-1 타이밍).
- **커맨드 노출** = 마켓플레이스 `skills` 배열에 vet 스킬 경로를 싣고 `/vet`
  (또는 `/vet:vet`)로 발동.

## Out of Scope (v2 백로그 후보)

- 복수 초안 경쟁(best-of-N 선별·합성) — 열린 질문 커버리지 후보. v1에서 반박
  게이트 단일 메커니즘 고정을 위해 제외(D-3, FR-019).
- 층위 2·3의 자동 트리거(옵트인이 아닌 감지형 발동) — 층위 2는 항상 켜짐이지만
  층위 3(/vet)은 명시 옵트인 유지(FR-010).
