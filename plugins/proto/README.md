# proto

해석 갈림 스프린트. 본 빌드 직전 5분 — 흐릿한 아이디어 한 줄을 **스타일이 아니라 해석에서 갈라지는** 저충실도 스케치 3장으로 그려 나란히 보여주고, 객관식 판정 하나를 받고, 고른 스케치와 판정 몇 줄만 남기고 끝낸다.

## 존재 이유

텍스트 스펙은 의도를 과소결정한다. 같은 문장을 읽고도 사람과 AI는 서로 다른 화면을 상상하고, "맞긴 한데 쓸모없다"는 판정은 문서가 아니라 실물에서만 나온다. proto는 그 갈림을 본 빌드가 시작되기 **전에, 5분 안에** 한 번 드러낸다.

이 도구는 스프린터다. 캠페인 엔진이 아니다 — 기본 1라운드, 최대 2라운드로 끝나고, 워커 위임도 검증 파이프라인도 데이터 수확도 없다. 스프린트로 안 풀리는 씨앗이면 도구를 키우는 게 아니라 인터뷰·스펙 작업으로 넘기는 게 답이다.

산출물은 **의도의 증거**(고른 스케치 1장 + verdict.md)이지 본 제품이 아니다. 본 빌드는 이 둘을 입력으로 삼아 처음부터 새로 짓는다.

## 설치

```
/plugin marketplace add chenjingdev/chenjing-plugins
/plugin install proto@chenjing-plugins
```

## 사용법

```
/proto:proto <흐릿한 한 줄 아이디어>
```

예: `/proto:proto 내 하루를 기록하는 뭔가`

빌드 전 질문은 없다. 갤러리가 몇 분 안에 뜨고, 실물을 앞에 두고 객관식 판정을 묻는다.

## 흐름

1. **입력** — 한 줄 아이디어. 되묻지 않는다.
2. **갈림축 선택** — 이 아이디어에서 해석이 실제로 갈리는 축 하나를 자동 선택(telos·자세·입도·시점·주도권, 없으면 발굴). 세 스케치는 그 축 위의 세 지점.
3. **직접 3장 스케치** — 메인 세션이 워커 없이 직접 그린다. 각각 흑백 와이어프레임(회색 박스+라벨+핫스팟, ≤200줄), self-contained HTML 한 장. 데이터는 현실적인 라벨 몇 줄이면 충분 — 수확 원정 없음.
4. **한 번 훑기** — 셋이 구조에서 진짜 갈리는지, 배선 안 된 가짜 표면이 없는지 눈으로 확인하고 약한 파일은 그 자리에서 고친다.
5. **갤러리 제시** — 격리 iframe 3칸 갤러리를 렌더로 제시하고 세 파일을 브라우저 탭으로도 연다. 헤더는 갈림 지점을 평문 한 문장으로 말한다.
6. **판정** — "어느 해석이 의도에 가장 가깝나?" (A/B/C/전부 아님). 전부 아님이면 어긋난 지점 하나를 묻고 **더 좁은 질문**으로 라운드 2를 한 번만 더 — 라운드 2의 판정으로 무조건 종료. 라운드 3은 없다.
7. **핸드오프** — verdict.md(축·세 해석 한 줄·판정·사용자 원문 인용·방향 한 줄) + survivor.html(이 위에 짓지 말라는 배너 포함)만 남기고 나머지는 삭제.

## 산출물

`.proto/<타임스탬프>-<슬러그>/` 아래 두 파일:

- **`verdict.md`** — 판정 기록 몇 줄. 요구사항 에세이가 아니라 판정 비트와 사용자 원문 인용.
- **`survivor.html`** — 고른 스케치. 상단 배너: *"이 파일은 의도의 증거입니다. 본 빌드는 이 코드 위에 짓지 말고 처음부터 새로 지으세요."*

본 빌드로 넘어갈 때 이 두 파일을 **입력**으로 쓴다. survivor의 코드를 이어서 확장하지 않는다.

## 원칙

- **빌드 전 질문 0개** — 제1계율. 갤러리가 5분 안에 오니까 지키는 비용도 0이다.
- **N=3, 축은 하나** — 라운드마다 정확히 세 스케치, 한 갈림축 위의 세 지점.
- **스타일이 아니라 해석이 다르다** — 스킨 셋이면 실패.
- **와이어프레임 캡 + 그린 것은 전부 진짜** — 흑백 박스·라벨·핫스팟까지만. 살아있는 로직 없음. 배선 안 되는 UI(비활성 탭, 안 열리는 메뉴)는 아예 그리지 않는다.
- **직접 그린다** — 워커 위임 없음. 이 크기의 스케치엔 위임 오버헤드가 스프린트 예산 전부다.
- **기본 1라운드, 최대 2** — 거절에 더 큰 개념으로 답하지 않는다. 라운드 2는 반드시 더 좁게.
- **30초 판정** — 갤러리가 뜨고 30초 안에 갈림이 보여야 한다. 안 보이면 스케치 스코프가 넓은 것이지 사용자 탓이 아니다.
