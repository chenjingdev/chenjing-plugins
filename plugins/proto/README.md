# proto

해석-발산 병렬 프로토타이핑. 흐릿한 아이디어 한 줄을 **스타일이 아니라 해석에서 갈라지는** 실물 프로토타입 3개로 병렬 구현해 나란히 보여주고, 사용자는 실물 위에서 객관식 판정만 한다. 코드는 버리고 판정을 축적한다.

## 존재 이유

텍스트 스펙은 의도를 과소결정한다. 같은 문장을 읽고도 사람과 AI는 서로 다른 화면을 상상한다. "맞긴 한데 쓸모없다"는 판정은 문서가 아니라 실물에서만 나온다. 그리고 생성 비용이 사실상 0인 시대에는, 실물 N개를 만들어 그중 하나를 고르는 것이 인터뷰보다 싸다.

proto는 그 전제 위에서 동작한다. 흐릿한 한 줄을 받으면 **빌드 전에 사용자에게 아무것도 되묻지 않고** 곧바로 세 개의 실물을 만든다. 세 개는 색이나 문구가 다른 게 아니라 아이디어를 *어떻게 해석했는가*가 다르다 — 무엇을 위한 도구인지(telos), 사용자의 자세, 다루는 단위의 입도, 시점, 주도권 중 이 아이디어에서 실제로 갈리는 한 축을 골라 그 축 위의 세 지점으로 만든다. 사용자는 실물을 눌러보고 객관식으로 판정만 한다. 생성하는 쪽은 사용자가 아니다.

이 도구가 내놓는 것은 **의도의 증거**(생존 프로토타입 1개 + 판정 ledger)이지 본 제품이 아니다. 본 빌드는 이 실물 위에 얹지 말고, ledger의 판정과 생존 실물을 입력으로 삼아 처음부터 새로 짓는다.

## 설치

```
/plugin marketplace add chenjingdev/chenjing-plugins
/plugin install proto@chenjing-plugins
```

## 사용법

```
/proto:proto <흐릿한 한 줄 아이디어>
```

예: `/proto:proto 내 하루를 기록하는 뭔가`

빌드 전 질문은 없다. 첫 갤러리가 뜨고 나서야, 실물을 앞에 두고 객관식 판정을 묻는다.

## 흐름 요약

1. **입력** — 한 줄 아이디어. 되묻지 않는다.
2. **substrate 분류** — UI형 / CLI형 / 파이프라인·데이터형 중 하나로 자동 분류. 어느 쪽이든 최종 산출은 self-contained HTML 한 장이라 갤러리 방식은 동일하다.
3. **해석 갈림축 확정** — 이 아이디어에서 해석이 실제로 갈리는 축 하나를 자동 선택(강한 축이 없으면 아이디어에서 새로 발굴).
4. **공유 데이터셋 저작** — 목 데이터 1벌을 만들어 세 후보가 공유. 빈 구간·깨진 레코드·폭주 구간을 데이터에 심는다.
5. **병렬 생성 (N=3)** — 빌더 3개를 한 번에 병렬 실행. 각 후보는 4상태(폭주=첫 화면 / 빈 상태 / 오류 / 로딩)를 자체 in-frame 토글로 전환. 대기 중에는 "지금 만드는 중인 3개 해석"과 예상 소요를 정직하게 보여준다.
6. **검증 게이트** — 세 후보의 소스를 읽어 4상태가 실재하는지, 그리고 **셋이 구조·상호작용에서 실제로 갈리는지** 확인. 두 후보가 같은 구조에 스킨만 다르면 해당 빌더만 1회 재생성, 그래도 안 갈리면 다른 축으로 전환하고 그 사실을 알린다.
7. **갤러리 제시** — 세 후보를 격리 iframe으로 나란히 임베드한 단일 갤러리를 렌더로 제시. 각 프레임 위에 해석 라벨.
8. **판정** — 실물을 앞에 두고 객관식. "어느 해석이 의도에 가장 가깝나?" (A/B/C/전부 아님). '전부 아님'이면 어긋난 지점을 물어 다음 라운드의 축을 조정한다.
9. **ledger 축적 → 종료·핸드오프** — 라운드마다 판정 비트와 방향만 ledger에 적는다. 판정이 안정되면(최대 3라운드) 종료: 생존 실물 1개를 보존하고 나머지는 버린다.

## 산출물

실행 결과는 프로젝트의 `.proto/<타임스탬프>-<슬러그>/` 아래에 남는다.

- **`ledger.md`** — 라운드별 판정 기록. 각 블록은 (축, 후보 3개의 해석 한 줄, 판정 결과, 어긋난 지점, 다음 방향 벡터)와 실물 앵커만 담는다. **산문 요구사항은 적지 않는다** — 이 도구는 요구사항을 서술하는 곳이 아니라 판정을 축적하는 곳이다.
- **`survivor.html`** — 살아남은 프로토타입 한 장. 파일 상단에 배너 주석이 박혀 있다:

  > 이 파일은 의도의 증거입니다. 본 빌드는 이 코드 위에 짓지 말고 처음부터 새로 지으세요 — ledger.md의 판정과 이 실물을 입력으로만 쓰세요.

본 빌드로 넘어갈 때는 이 두 파일(`ledger.md`, `survivor.html`)을 **입력**으로 쓴다. survivor의 코드를 이어서 확장하지 않는다.

## 원칙

- **빌드 전 질문 0개** — 이 스킬의 제1계율. 되묻지 않고 먼저 실물을 만든다.
- **N=3 고정** — 라운드마다 정확히 세 후보.
- **스타일이 아니라 해석이 다르다** — 세 후보는 같은 것의 스킨이 아니라 서로 다른 해석이다. 두 개가 스킨만 다르면 게이트에서 걸린다.
- **사용자는 판정만 한다** — 발산·생성은 시스템의 몫, 사용자는 실물 위에서 객관식 판정만 한다.
