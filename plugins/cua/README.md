# CUA for Claude Code

Claude Code에서 Mac의 앱과 브라우저를 Codex CUA로 조작하는 플러그인입니다. **macOS 전용 · 비공식 실험 버전**입니다. 이 문서는 0.7.0 기준입니다.

## 준비

- Claude Code와 Computer Use를 사용할 수 있는 Codex 데스크톱 앱이 필요합니다.
- Python 3.9 이상이 필요합니다. 첫 설정에서 필요한 패키지를 전용 환경에 내려받습니다.
- macOS 접근성·화면 기록 권한은 원본 Codex 앱의 안내에 따라 설정합니다.
- 메뉴 막대 앱 CUA Bar는 필수가 아닙니다. 쓰려면 Apple Silicon Mac과 macOS 14 이상이 필요합니다.

## 설치와 사용

```sh
claude plugin marketplace add chenjingdev/chenjing-plugins
claude plugin install cua@chenjing-plugins --scope user
```

Claude Code의 새 대화에서 다음을 실행합니다.

```text
/cua:setup
```

Claude가 설치와 연결을 점검합니다. 이후 **“cua 써서 이 앱을 확인해 줘”**처럼 요청하면 됩니다. 연결이 끊겼다면 **“CUA 연결 복구해 줘”**라고 요청합니다.

설정이 끝나면 Codex를 따로 준비하지 않아도 됩니다.

- **앱을 평소처럼 켜도 됩니다.** 설정 때 로그인 항목(`~/Library/LaunchAgents/com.chenjingdev.codex-cua.env.plist`)이 등록돼, Dock이나 Spotlight로 연 Codex도 연결 가능한 방식으로 켜집니다. 시스템 설정의 로그인 항목에는 이 항목이 실행하는 스크립트 이름 `codex-cua-login-env`로 보입니다.
- **앱이 꺼져 있어도 됩니다.** Claude가 CUA에 연결할 때 Codex를 뒤에서 열고, 앞에 있던 앱으로 포커스를 돌려줍니다. Codex를 켜는 것은 새 Claude 대화가 CUA에 연결할 때와, 연결이 끊긴 뒤의 다음 CUA 호출뿐입니다. 대화 끝 정리(`turn_ended`)는 켜지 않습니다.
- **설정 전부터 켜져 있던 Codex는 한 번 다시 켜야 합니다.** CUA Bar는 이런 Codex를 끄지 않고 알림으로 다시 켤지 묻고, **다시 켜기**를 누르면 정상 종료한 뒤 다시 켭니다. 앱 없이 하려면 진행 중인 작업을 마치고 Codex를 정상 종료(⌘Q)한 뒤 다시 엽니다. 어느 쪽도 강제로 종료하지 않지만, 다시 켜면 하던 Codex 작업은 끊깁니다. 다시 켠 뒤에도 Claude Code에서 cua가 연결되지 않은 것으로 보이면 `/mcp`로 다시 연결합니다.
- **Codex가 꺼졌다 켜져도(앱 갱신 포함) 열려 있던 Claude 대화는 이어집니다.** 다음 CUA 호출 때 새 호스트에 다시 붙습니다. 연결이 끊길 때 하던 조작은 다시 보내지 않으므로 그 조작이 실제로 됐는지는 알 수 없습니다. 화면을 확인한 뒤에 이어 갑니다.
- Codex가 뒤에서 열리는 동안 로그인·권한·업데이트 창이 떠 있으면, 기다리다가 Codex를 앞으로 띄우고 안내합니다.
- **플러그인에 문제가 있어도 Codex는 켜집니다.** 연결용 파이썬 환경이나 `command.py`가 없을 때, 환경이 아직 준비되지 않았을 때(Codex를 켜는 동안에는 복구하지도 기다리지도 않습니다), 등록된 플러그인이 없거나 필요한 파일이 빠졌거나 손상됐을 때, 연결을 시작하기 전에 상태 폴더·점유 같은 설정이 막혔을 때 Codex는 연결 없이 원래대로 켜집니다. CUA 연결만 빠지므로 `/cua:setup`으로 복구합니다.
- 다음은 이 보호 밖입니다. `~/.local/share/codex-cua` 폴더 전체를 `codex-cua uninstall` 없이 지운 경우, `command.py` 자체에 문법 오류가 있는 경우, 설정 때 Codex 실행 파일 경로를 기록하지 못했거나 기록한 경로가 앱 업데이트로 바뀐 경우(`/cua:setup`으로 다시 기록), 연결 가능한 방식으로 시작한 뒤에 생긴 오류입니다. Claude Code에 등록된 플러그인이 0.7.0보다 낮은 판이면 Codex 시작도 그 판의 코드가 맡으므로 그 판의 보호만 받습니다.

## CUA Bar (메뉴 막대 앱)

CUA Bar는 연결 상태를 보고 놓아주기·종료를 하는 macOS 메뉴 막대 앱입니다. 선택 사항이라 앱 없이 이 플러그인만으로도 CUA를 쓸 수 있습니다.

- **받는 곳.** 이 저장소의 [GitHub Releases](https://github.com/chenjingdev/chenjing-plugins/releases)에서 태그 `cua-bar--v0.7.0`의 `CUABar-v0.7.0-macos-arm64.zip`을 받습니다. Apple Silicon·macOS 14 이상용이고, ad-hoc 서명만 했으며 공증은 하지 않았습니다. 설치와 처음 여는 방법은 [앱 README](../../apps/cua-bar/README.md)를 봅니다.
- **플러그인을 설치하고 갱신합니다.** 앱이 이 플러그인(`cua@chenjing-plugins`)을 깔고 설정(`codex-cua setup`)까지 합니다. 앱과 플러그인의 판이 다르면 문제로 알리고, 맞는 판 받기를 고치는 버튼으로 둡니다. 갱신하면 새 Claude 대화부터 새 판이 붙습니다. 새 앱 버전이 나왔는지는 하루에 한 번 이 저장소의 앱 태그로 확인합니다. 새 버전이 있으면 창 아래에 **새 버전 x.y.z** 버튼이 생기고, 버전마다 한 번 알림이 옵니다.
- **로그인할 때 자동으로 뜹니다.**
- **끄지 않습니다.** 사용자가 누르기 전에는 Codex·Chrome·AI를 끄지 않고, 어떤 창도 앞으로 가져오지 않습니다.
- **자동 정리와 알림.** AI 대화가 정리 없이 끝나면 앱이 대신 점유를 놓아줍니다. 세션 ID로 콕 집어 푸는 것은 Claude 연결의 세션만 저절로 하고, Codex 대화의 세션은 사용자가 누를 때만 합니다. 알림은 세 가지뿐입니다. 연결 없이 켜진 Codex를 다시 켤지 묻는 알림, 점유가 오래 남았다는 알림, 새 앱 버전 알림입니다.
- **앱을 꺼도 연결은 그대로 됩니다.** 앱은 연결이 지나는 길목이 아닙니다. 앱을 끄면 상태 보기와 자동 정리만 멈춥니다.

**아이콘**은 메뉴 막대에 하나뿐이고, 색이 아니라 모양으로 상태를 구분합니다. 올려 두면 한 줄 요약이 뜨고, 누르면 창이 열립니다.

- 체크 표시 원은 **준비**입니다. Codex가 꺼져 있어도, Claude 대화를 열 때 켤 수 있으면 준비입니다.
- 도는 화살표는 **작업 중**입니다. CUA 호출이 진행 중이거나 10초 안에 있었습니다.
- 경고 삼각형은 **문제**입니다. 문제가 있으면 다른 상태보다 먼저 보입니다.

창의 맨 위 상태 카드에는 문제와 다음에 할 일 한 줄, 그리고 고치는 버튼이 있습니다.

- 연결 없이 켜진 Codex는 **다시 켜기**, 끝난 연결이나 주인 없는 점유는 **놓아주기**입니다. 놓아 본 뒤에도 끝난 연결이 남으면 버튼이 **끝난 연결 끄기**로 바뀌고, 끄기 전에 한 번 묻습니다.
- 플러그인이 없거나 판이 다르면 **설치·갱신**(맞는 판 받기), 래퍼나 중계기가 깨졌으면 **고치기**입니다.
- Codex가 없으면 **받는 곳 열기**, 상태를 읽지 못하면 **다시 읽기**입니다.

그 아래에 탭이 네 개 있습니다.

- **연결**: Claude와 Codex의 CUA 연결 목록입니다. 작업 폴더, 시작 시각, 메모리, 상태(사용 중, 30분 넘게 쉼, 대화는 사라졌는데 런타임이 남은 끝남, 알 수 없음)가 보이고, 줄마다 놓아주기·끄기·강제 종료가 있습니다. 아래에는 묶음 끄기(전체·Claude만·Codex만)와 끝난 연결 놓아주기가 있습니다.
- **브라우저 점유**: 연결까지 사라졌는데 Chrome에 남았을 수 있는 점유(주인 없는 점유)와, 세션 ID로 콕 집어 풀기입니다. 안 풀리면 "막힌 탭 닫기"를 먼저 안내하고, 마지막으로 "확장 끄고 켜기"를 그때 끊길 살아 있는 연결 목록과 함께 안내합니다.
- **다른 도구**: cmux-cua 같은 다른 도구의 상태와, 지금 어느 AI가 화면을 쓰는지입니다. cmux-cua 연결마다 **끄기**가 있고, 그 연결만 정상 종료하며 cmux-cua 본체는 끄지 않습니다.
- **기록**: 최근 조작 기록(시각·연결·도구 이름·성공 여부·걸린 시간)과 진단 복사 버튼입니다.

**제거**는 창 아래의 제거 버튼입니다. 한 번 확인하면 연결 설정과 중계기를 되돌리고(`codex-cua uninstall`과 같은 일), 로그인할 때 뜨는 등록을 지운 뒤 앱을 끝냅니다. 그다음 `CUABar.app`을 휴지통으로 옮깁니다. Codex가 켜져 있으면 정상 종료한 뒤 다시 하라고 안내만 하고 아무것도 바꾸지 않으며, Codex를 대신 끄지 않습니다. Claude 플러그인은 남으므로 지우려면 아래 [관리](#관리)의 명령을 씁니다. 제거 버튼을 쓰지 않고 앱 파일만 지워도 Codex는 원래대로 켜지고 CUA 연결도 그대로 됩니다.

## 중계기

0.7.0부터 Codex를 켤 때 Codex가 CUA 런타임을 띄우는 자리에 중계기를 끼웁니다. `codex-cua setup`이 `~/.local/share/codex-cua/relay/`에 고정 사본을 두고, Codex를 켤 때마다 이 사본을 쓰며 필요하면 새로 고칩니다. 중계기는 런타임과 주고받는 내용을 그대로 전달하면서 세 가지를 더합니다.

- **끄기 전에 탭을 놓아줍니다.** 열린 대화의 범위를 알고 있어서, 연결을 끄기 전에 AI가 정상 종료 때 하는 정리와 같은 놓아주기를 합니다. AI가 만든 임시 탭은 닫히고, 사용자 탭과 넘겨주려고 남긴 탭은 그대로 둡니다.
- **Codex 연결이 목록에 보입니다.** Codex 대화의 런타임이 작업 폴더, 작업 중·쉼, 세션 ID와 함께 연결 목록에 올라옵니다.
- **조작 기록을 남깁니다.** 시각, 연결, 세션 ID, 도구 이름, 성공 여부, 걸린 시간만 `activity.jsonl`에 한 줄씩 적습니다. Claude 대화의 런타임이면 그 대화를 연 다리의 이름(다리의 pid와 시작 시각)도 줄마다 적어서, 대화가 끝나 연결이 사라진 뒤에도 기록 탭이 그 줄을 Claude의 것으로 보입니다. 파일이 256KB를 넘으면 최근 200줄만 남기고 줄이며, 상태에는 최근 200개가 보입니다(아래 [개인정보](#개인정보)).

중계기는 `~/.codex/config.toml`을 고치지 않습니다. Claude 대화의 런타임에는 Codex를 켜는 래퍼가 원래 `cua_repl` 정의를 읽어 그 앞에 끼웁니다. Codex 앱이 대화마다 보내는 `cua_repl` 설정에서는 런타임 경로 한 값만 중계기로 바꿔 전달하고, 예상한 값일 때만 바꾸며 나머지는 그대로 넘깁니다. 모델·권한·승인 설정은 건드리지 않습니다.

중계기가 없어도 Codex는 켜집니다. 원래 정의를 읽지 못하거나 중계기가 깨졌으면 Codex는 중계기 없이 원래대로 켜집니다. 그때는 Codex 대화의 연결을 끄기 전에 탭을 놓지 못하고, 작업 중·쉼·세션 ID도 알 수 없습니다. 중계기 사본이 없거나 깨졌으면 CUA Bar가 문제로 알리고 **고치기**로 고칩니다(`/cua:setup`도 같은 일을 합니다). 원래 정의를 읽지 못해 중계기 없이 켜진 경우는 `status --json`의 `setup.relay`가 `inactive`로만 보이고 CUA Bar는 문제로 알리지 않습니다. 이유는 `codex-cua diagnose`의 `relay left out …` 줄에 나옵니다. 이번 설정보다 먼저 켜진 Codex는 `host.started_before_setup`이 `true`이고, CUA Bar 카드가 "Codex를 다시 켜면 새 설정이 적용돼요"라고 안내합니다. 그 전에는 연결 상태를 모르거나 놓아주지 못할 수 있습니다.

## 관리

이전 `codex-computer-use` 플러그인에서 옮길 때는 마켓플레이스를 갱신하고 이전 플러그인을 제거한 뒤 새 이름으로 설치합니다. 연결용 로컬 명령 `codex-cua`는 그대로 사용하며, 새 설정을 실행하면 연결 대상이 `cua`로 갱신됩니다.

```sh
claude plugin marketplace update chenjing-plugins
claude plugin uninstall codex-computer-use@chenjing-plugins --scope user
claude plugin install cua@chenjing-plugins --scope user
```

새 Claude Code 대화에서 `/cua:setup`을 실행합니다.

설정 스킬이 설치한 명령은 직접 실행할 수도 있습니다. 놓아주기·끄기·다시 켜기는 사람이 직접 부르거나 CUA Bar에서 누르는 명령입니다. AI는 `doctor`·`status --json`·`diagnose`만 씁니다(설치는 `/cua:setup`이 합니다). `codex-cua`는 언제나 지금 설치된 플러그인 판의 코드를 실행하므로, 플러그인이 자동으로 갱신돼도 새 명령이 바로 나타납니다. 상태 확인·놓아주기·종료 명령은 아래 [고급 명령](#고급-명령)에 있습니다.

```sh
~/.local/bin/codex-cua doctor --probe  # 연결 확인
~/.local/bin/codex-cua start           # 연결 가능한 방식으로 Codex 실행(보통은 필요 없음)
```

업데이트는 다음 명령으로 적용합니다. 이미 열려 있던 Claude 대화는 작업을 마친 뒤 새로 엽니다. CUA Bar를 쓰면 앱의 맞는 판 받기가 같은 일을 합니다.

```sh
claude plugin marketplace update chenjing-plugins
claude plugin update cua@chenjing-plugins --scope user
~/.local/bin/codex-cua setup
```

0.6.0 이하에서 올릴 때는 마지막 줄 대신 새 Claude Code 대화에서 `/cua:setup`을 실행합니다. 이전 판의 `codex-cua`는 새 판의 설정을 모두 알지 못해서, 이 한 번만 필요합니다.

제거할 때는 진행 중인 Codex 작업을 마치고 Codex 앱을 정상 종료한 다음 실행합니다. 로그인 항목, 등록한 설정값, 중계기 사본과 설치한 명령도 함께 지웁니다.

```sh
~/.local/bin/codex-cua uninstall
claude plugin uninstall cua@chenjing-plugins --scope user
```

## 고급 명령

CUA Bar가 쓰는 명령을 직접 부를 수도 있습니다. 모두 `~/.local/bin/codex-cua` 뒤에 붙입니다. 이 명령들은 JSON 객체 하나만 출력하고(`diagnose`는 글), 동작이 실패해도(`"ok": false`) 종료 코드는 0입니다. 종료 코드가 0이 아니면 명령을 실행하지 못한 것입니다. 연결 id(`<ID>`)는 `status --json`의 `connections`에서 찾고, cmux-cua 연결의 id는 `other_tools[].clients[].id`에서 찾습니다. 놓아주기·끄기·다시 켜기는 사람이 직접 부르거나 CUA Bar에서 누르는 명령이고, AI는 `doctor`·`status --json`·`diagnose`만 씁니다.

- `status --json`: 지금 상태(Codex·호스트·설정, 연결 목록, 남았을 수 있는 점유, 다른 도구, 최근 조작 기록)를 보여 줍니다. 아무것도 놓거나 끄지 않습니다(끝난 기록만 정리).
- `release --connection <ID>` 또는 `release --ended`: 연결 하나의 탭을, 또는 끝난 연결의 탭을 놓아줍니다. `--ended`는 주인이 사라진 Claude 세션도 세션 ID로 풀어 보는데, 이때 살아 있는 런타임을 거쳐 브라우저를 한 번 부릅니다. 연결의 놓아주기가 확인되면(`stop`의 놓아주기 단계도 같습니다) 그 연결이 맡던 세션은 죽은 브리지 기록에서도 지워서, 이미 풀린 세션이 `status --json`의 남았을 수 있는 점유에 남지 않습니다. 중계기나 브리지가 "끝났는지 확인하지 못했다"(`cleanup_not_confirmed`)고 답하면 같은 연결에 한 번 더 묻습니다(런타임이 한도보다 조금 늦게 끝냈을 수 있어서 탭은 닫혔는데 범위만 열려 있는 일이 있습니다). 두 번째 물음에서야 확인된 놓아주기는 죽은 브리지 기록에서 바로 지우지 않습니다. 두 번째 답은 런타임이 그 턴의 끝을 이미 받았다는 뜻일 수 있어서, 그 세션은 `--ended`가 이어서 세션 ID로 브라우저를 불러 풀어 봅니다. 다른 까닭(`timeout`, `request_in_flight`, `no_trusted_scope` 등)에는 다시 묻지 않습니다.
- `release-session --session <세션ID> [--user]`: 주인이 사라진 세션의 점유를 세션 ID로 콕 집어 풉니다.
- `stop --connection <ID> [--force]`: 연결 하나를 끕니다. 먼저 탭을 놓아주고(cmux-cua 연결은 놓아줄 점유가 없어 곧바로) 정상 종료를 요청하며, `--force`는 그래도 남은 연결 프로세스만 강제로 종료합니다.
- `stop --group all|claude|codex [--force]`: Claude·Codex 연결을 묶음으로 끕니다. cmux-cua 연결은 어느 묶음에도 들어가지 않습니다.
- `restart-codex`: Codex를 정상 종료한 뒤 다시 엽니다.
- `diagnose`: 대화에 붙여넣어도 되는 진단 글을 출력합니다. Codex가 이미 끝난 대화의 스레드를 스스로 다시 켠 빈 런타임은 `status --json`의 연결 목록에 넣지 않고 이 글에 개수와 메모리 한 줄로만 적습니다. 죽은 다리의 이름을 달았는데 그 다리의 기록이 없고 한 번도 불리지 않았고 열린 범위도 없는 런타임 가운데, 중계기가 켜지며 그 다리가 이미 돌고 있지 않은 것을 본 것(대화가 18초 만에 끝났어도 같습니다)과, 그렇게 기록하지 않은 것(다리가 돌고 있었다고 적었거나, 확인하지 못했거나, 기록이 없는 옛 중계기)이면 그 다리보다 2분 넘게 늦게 켜진 것입니다. Codex가 그 스레드를 내릴 때(마지막 사용 뒤 약 30분) 같이 사라집니다. 한 번이라도 불렸거나 범위를 가졌으면 지금처럼 끝난 연결입니다.

안전 규칙은 다음과 같습니다.

- `release-session`은 주인이 사라진 세션만 풉니다. 살아 있는 연결이 쓰는 세션은 `session_live`로, 기록에 없는 세션은 `not_found`로 거절합니다. Codex 대화의 세션은 나중에 다시 열 수 있으므로 `--user`(사용자가 직접 누른 일)를 붙일 때만 풀고, 안 붙이면 `needs_user`로 거절합니다. 다만 기록의 `owner`가 다리 이름인 중계기가 적은 세션은 Claude 다리가 연 일회용 대화의 것이라 다시 이을 수 없으므로 Codex 대화로 보지 않고 `--user` 없이 풉니다(그 다리가 살아 있는 동안은 `session_live`). AI는 `--user`를 붙이지 않고, AI가 쓰는 MCP 도구에는 이 기능이 없습니다.
- `release --ended`는 살아 있는 연결이 지금 쓰는 점유를 건드리지 않습니다. `release --connection`을 일하는 중인 연결에 쓰면 하던 브라우저 작업의 탭이 닫히고, Codex 대화는 그 턴의 다음 브라우저 조작이 시간 초과까지 멈춥니다. CUA Bar는 이럴 때 한 번 묻습니다.
- `stop`은 연결 프로세스(Claude의 브리지, Codex 대화의 런타임, cmux-cua 연결의 `cmux-cua mcp`)만 끕니다. Codex 앱, AI 클라이언트, Chrome, cmux-cua 데몬(`serve`)은 어떤 경우에도 끄지 않습니다. cmux-cua 연결은 `stop --connection cmux-…`로 하나씩만, 놓아주기 없이 끄며 묶음 종료에는 들어가지 않습니다. 끄면 그 AI 대화의 cmux-cua 도구는 다시 붙을 때까지 끊깁니다.
- `stop --group codex`는 주인을 알 수 없는 연결을 건너뜁니다(`unattributed`). Claude 대화의 런타임일 수 있기 때문이며, 그런 연결은 하나씩 끄거나 `--group all`로 끕니다.
- `restart-codex`는 정상 종료(⌘Q와 같은 종료 요청)만 하고 강제로 종료하지 않습니다. Codex가 꺼져 있으면 `not_running`이고 아무것도 켜지 않으며, 종료 창에서 사용자가 취소하면 `quit_cancelled`입니다. Codex가 종료 요청을 받고도 30초 안에 꺼지지 않으면 `quit_pending`이고, 메뉴 막대 앱이 Codex가 꺼지기를 기다렸다가 다시 엽니다. 하던 Codex 작업이 끊기므로 사용자가 직접 부를 때만 씁니다.

## 개인정보

- 연결과 조작 기록은 이 맥의 `~/Library/Caches/codex-cua`에만 남습니다(폴더는 본인만 쓸 수 있고 파일은 0600). 들어 있는 것은 프로세스 번호(pid)와 시작 시각, 작업 폴더, 세션 ID와 턴 ID(아직 끝나지 않은 범위의 짝), 제어 소켓 경로, 작업 중·정리 상태(busy, cleanup), 중계기가 켜질 때 그것을 연 다리가 돌고 있었는지(예·아니오·확인 못 함), 시각, 도구 이름, 성공 여부(ok)와 걸린 시간(ms)뿐입니다. 이 맥 밖으로 보내지 않습니다.
- 도구에 넘긴 인자와 결과, js 코드와 제목, URL, 화면, 환경 값, 시크릿은 기록하지 않습니다. 점유를 세션 ID로 풀 때도 탭 개수만 셉니다.
- `codex-cua diagnose`의 글은 붙여넣어도 되도록 홈 폴더를 `~`로 쓰고, URL을 지우고, 작업 폴더와 환경 값은 넣지 않습니다.
- `~/Library/Caches/codex-cua`는 `codex-cua uninstall`이 지우지 않습니다. 필요 없으면 직접 지웁니다.

## 알아둘 점

- Codex의 원본 CUA를 호출합니다. Codex 앱 파일과 모델 설정은 수정하지 않으며, Claude 연결마다 별도의 임시 대화를 사용합니다.
- 원본 CUA의 접근 권한·브라우저 정책·파일 제한이 적용됩니다. 표준 form 승인만 전달하며, 지원하지 않는 승인 흐름은 실패를 알립니다.
- 내부 Codex 인터페이스를 사용하므로 앱 업데이트 후 플러그인 업데이트나 재연결이 필요할 수 있습니다. Claude 매 턴 자동 종료와 MCP cancellation 중계는 지원하지 않습니다.
- Codex가 `cua_repl` 서버를 번들 CUA 플러그인으로도, 이 플러그인의 중계기로도 식별하지 못하면(설정으로 바꾼 다른 중계기 등) 연결하지 않고 오류를 알립니다.
- 앱이 기본 위치에 없다면 `CODEX_CUA_APP_PATH`에 원본 `.app`의 절대 경로를 지정합니다. 상태 폴더를 `CODEX_HOST_CUA_STATE_DIR`로 바꾸는 경우 호스트와 MCP에 같은 값을 지정하고, 현재 사용자 소유의 비공개 폴더를 사용합니다.
