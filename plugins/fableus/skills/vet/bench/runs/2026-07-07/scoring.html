prettier --write "$f"; } ``` 환경 변수 `CLAUDE_PROJECT_DIR`(프로젝트 루트)도 사용할 수 있습니다. ## 3. 종료 코드와 차단(blocking) - **exit 0** — 성공. stdout은 기본적으로 transcript(Ctrl-O)에서만 보입니다. 예외: **UserPromptSubmit과 SessionStart에서는 stdout이 Claude의 컨텍스트에 주입**됩니다 (이 세션의 "SessionStart hook additional context"가 바로 그 경로입니다). - **exit 2** — 차단 에러. 이벤트에 따라 의미가 다릅니다: - **PreToolUse**: 도구 호출 자체를 차단하고, stderr를 Claude에게 피드백합니다. - **PostToolUse**: 도구는 이미 실행됐으므로 차단은 못 하고, stderr를 Claude에게 보여 대응하게 합니다. - **UserPromptSubmit**: 프롬프트 처리를 차단하고 프롬프트를 지웁니다. stderr는 사용자에게만 표시됩니다. - **Stop**: 종료를 차단합니다(Claude가 계속 작업하도록 강제). stderr는 Claude에게 전달됩니다. - **SessionStart, PreCompact, Notification**: 차단 개념이 없어서 stderr가 사용자에게만 표시되고 진행은 계속됩니다. - **그 외 코드(1 등)** — 비차단 에러. stderr를 사용자에게 보여주고 실행은 계속됩니다. exit code보다 정밀한 제어가 필요하면 exit 0으로 stdout에 **JSON을 출력**하는 방식이 있습니다: `continue: false`(중단), `decision: "block"` + `reason`, `systemMessage`(사용자 알림), `suppressOutput`, 그리고 `hookSpecificOutput`으로 PreToolUse의 `permissionDecision`(`allow`/`deny`/`ask` — 권한 프롬프트 자체를 대체) · `updatedInput`(도구 입력 수정), 각 이벤트의 `additionalContext`(모델 컨텍스트 주입) 등을 지정할 수 있습니다. ## 4. 다섯 이벤트의 발화 시점 - **PreToolUse** — Claude가 도구 호출 파라미터를 만든 직후, **실행 직전**. 권한 검사와 연계되며 호출을 막을 수 있는 유일한 지점입니다. - **PostToolUse** — 도구가 **성공적으로 완료된 직후**. (실패 시엔 별도 이벤트인 PostToolUseFailure가 있습니다.) - **UserPromptSubmit** — 사용자가 프롬프트를 제출한 시점, **Claude가 처리하기 전**. 컨텍스트 주입이나 프롬프트 검열에 쓰입니다. - **SessionStart** — 새 세션 시작 또는 재개 시. `source`로 신규 시작(`startup`), 재개(`resume`), `/clear` 후, compact 후를 구분합니다. - **PreCompact** — 컨텍스트 압축(compaction) **직전**. `trigger`가 `manual`이면 `/compact` 명령, `auto`면 컨텍스트 윈도우가 차서 자동 실행되는 경우입니다. 참고로 훅 편집 후에는 `/hooks` 메뉴를 열거나 재시작해야 반영되는 경우가 있고, 디버깅은 `claude --debug`로 훅 실행 로그를 보는 게 가장 빠릅니다.
